日期：2026-10-13。

## 目标与范围

让用户在同一会话内继承并修改查询条件，展示每轮改变了什么、继承了什么。上下文以最后一次成功的 QueryPlan 为准，澄清草稿与有效计划分别保存；每轮从数据库重新取数。

复用现有六指标、州与日或月分组、筛选、排序、Top N、语义目录、SQL 编译和安全边界。支持替换指标、时间和分组，添加或替换具体筛选，移除明确筛选，调整排序与 Top N。新增“最近半年”“近半年”作为最近六个自然月的表达，范围沿用现有包含分析基准所在月的定义。

首批每个会话最多 30 轮，包括失败和澄清轮次；达到上限后新建会话。模型只接收当前有效计划、受限草稿和必要的当前追问，不发送整段聊天或结果行。此阶段的记忆用于本会话查询条件，不增加跨会话偏好、结果归因、比较计算、品类关联、自由 SQL 或新 Agent 框架。

旧单轮 `/api/tasks` 输入、历史结果及 SSE 保持兼容；旧任务不批量转换成会话。前端新增会话模式，旧任务以单次问数展示。

## 用户行为与验收示例

| 输入或操作 | 预期 |
| --- | --- |
| 最近半年 GMV 按月统计 | 建立 GMV、最近六个自然月、月分组的有效计划 |
| 改成按州 | 继承指标和日期，仅将分组改为州；移除失效的月份排序并明确展示 |
| 那上个月呢 | 以同一分析基准解析上月，替换日期范围，继承其余条件 |
| 只看两个州，取前三名 | 要求补充具体州和排名方向；不查询，不覆盖有效计划 |
| SP 和 RJ，按 GMV 从高到低 | 补齐原草稿，保留“前三名”；筛选后最多两组，不补第三组 |
| 取消州筛选 | 只移除州筛选，保留时间、指标、订单状态及金额条件 |
| 再加上平均评分 | 在既有指标中增加评分，最多三个指标，整体检查权限 |
| 只看圣保罗州 | 可由模型补齐州名对应的受限筛选修改 |
| 改成按品类 | 说明能力边界；保留原有效计划和原草稿 |
| 没有有效前文时说“改成按州” | 澄清完整指标与时间，不猜测前文 |
| 另一个窗口提交了新追问 | 陈旧版本返回 409，刷新后重试，不自动合并 |
| 刷新页面或服务重启 | 恢复会话、历史轮次、有效计划及草稿，依据任务终态继续展示 |

“改成”表示替换相应条件，“再加”表示增加。无法确定操作范围或筛选目标时要求澄清。用户明确改动之外的字段必须保留。

相对日期始终以会话固定的分析基准解析，不按上一轮日期重新解释“本月”“上月”。“再往前一个月”等区间平移本批要求用户明确起止日期，不添加隐含的日期运算。

排名只有在原计划已有仍然有效的明确排序时才可继承；否则“前三名”要求说明排名指标与方向。只有一个指标时可确定排名指标，仍不凭“前三名”猜测升序或降序。筛选后的实际组数少于 N 时按实际组数展示。

更换维度时，代码移除引用旧维度的排序；改为整体时同时移除分组排名和 Top N，界面说明原因。换指标导致原排序指标失效时要求澄清，不自动选择另一个指标。所有自动联动来自明确的依赖规则，记录在修改说明中。

手动选择与文字表达采用同一冲突规则。会话输入框的空选择表示继承或从本轮识别，提交后清空手动覆盖，当前条件另行展示，避免上轮表单值冒充对话记忆。

## 受限修改与澄清

### 解析协议

首轮继续使用现有 QueryPlan 解析。追问产生 PlanDelta，规则完整识别则零模型调用，规则未完整识别时才由模型兜底。模型单次最多返回八个操作，成功响应只包含操作；无法表达完整意图时返回澄清及受限草稿，不返回 SQL 或完整替代计划。

| 操作 | 受限内容 |
| --- | --- |
| set_metrics | 替换为 1–3 个已授权指标 ID |
| set_dimensions | 替换为最多两个允许维度，允许空数组表示整体 |
| set_time_range | 明确的左闭右开日期范围 |
| add_filter | 添加语义目录中的一个类型正确的筛选 |
| replace_filter | 用服务端提供的筛选 ID 替换同字段的一个条件 |
| remove_filter | 移除一个已存在的筛选 ID |
| clear_filters | 移除明确指定字段的全部筛选 |
| set_order_by | 替换允许的排序列表，空数组表示清除 |
| set_top_n | 1–100 或 null 表示取消 Top N |

筛选 ID 根据基准计划的规范化条件生成，仅在该基准内有效。replace_filter 必须保持字段类型，不得借替换州筛选增加其他字段。重复、互相矛盾、引用不存在 ID 的操作要求澄清或拒绝；与 QueryPlan 联动清理分开记录。

例如“改成按州”返回：

```json
{"operations":[{"op":"set_dimensions","value":["state"]}]}
```

代码复制基准计划，应用修改和依赖规则，产生候选 QueryPlan，再校验指标、日期、筛选、排序及组合。规则识别出的明确修改作为硬约束逐项核对模型操作；未涉及字段保持不变。新解析器须覆盖否定和范围外检查，不能将追问拼成完整自然语言后交给旧规则猜测。

模型只获得允许的操作 schema、已授权目录、基准计划、草稿中已经确定的操作和当前追问。模型提出的是受限修改建议，字段和值仍由代码校验；无法完整表达句子时不能执行部分查询。最终修改说明由计划差异及依赖规则生成。

### 草稿与补充回答

needs_clarification 时保存草稿的基准计划版本、已验证操作、缺失字段、原始追问关联和最后一轮关联。有效计划不变，SQL 调用为零。任意字符串形式的模型草稿不可存入可信上下文。

回答“SP、RJ”仅补齐州值，不丢失此前的 Top N 等明确条件；若仍缺排序方向则继续澄清。补充回答不能改变草稿已明确条件，除非本轮明确说要修改；相互冲突时再次澄清。

用户可取消草稿并回到有效计划，或明确开始新的完整查询。取消草稿不执行 SQL；新完整查询先明确抛弃草稿，再由首轮解析建立计划。第一条问题需要澄清时同样允许补充，尚未完成的初始草稿不作为有效上下文。

初始草稿使用独立的受限结构保存已确定的指标、日期、维度和筛选等字段；缺少指标或日期时不能创建有效 QueryPlan。只有必需字段齐全且校验通过后才编译 SQL，不用占位指标补齐初始上下文。

模型格式错误、超时、SQL 失败、停止和范围外请求不推进有效计划。自动重试始终使用本轮固定的上下文快照，不继承正在变化的会话状态。无数据但成功完成的查询是有效计划。

## 持久化与状态更新

新增 conversations 表，保存租户、创建者、创建时角色、数据绑定、分析基准、语义目录摘要、会话版本、轮次计数、有效计划、草稿和当前任务关联。任务新增可空的会话 ID、轮次、请求 ID、受信任上下文快照及接纳版本；旧任务这些字段保持 NULL。

使用下一未占用迁移编号，当前为 003；不修改 001/002。会话与任务采用租户和人员的复合外键，任务的会话创建者必须一致。对会话内轮次和请求 ID 建唯一约束，当前任务关联通过复合外键保证属于该会话。

会话版本用于控制客户端新操作，execution_version 继续隔离任务尝试；两者不混用。状态更新规则：

1. 接纳新追问：锁定会话行，核对 expected_version、当前权限、数据绑定、轮次和无活跃任务，再在一个事务写入任务、outbox、固定上下文及活跃关联，会话版本增加一次。
2. 重复请求：相同 request_id 和相同输入返回原任务，不增加轮次；同 ID 不同输入返回 409。查重在陈旧版本判断之前进行，支持网络重发。
3. 成功完成：任务状态与 execution_version、会话接纳版本及活跃关联均匹配时，在同一事务保存任务结果、推进有效计划、清除草稿、释放活跃任务并增加会话版本。
4. 澄清：同一事务只更新已验证草稿、释放活跃任务并增加版本；失败或停止只释放活跃关联，保留有效计划和此前草稿。
5. 重试或租约重抢：不增加会话版本、不新建用户轮次；最后一个有效尝试完成后才推进上下文。旧尝试、重复完成和已取消任务不得写回计划。

所有新会话写路径统一使用“会话、任务、attempt”的锁顺序，兼顾停止、重试、租约到期及五分钟执行预算耗尽，避免遗漏活跃关联而永久占住会话。队列容量仍沿用现有全局限制。

取消草稿校验当前会话版本；停止澄清轮次只能取消当前关联的草稿，不能由旧轮次取消较新的草稿。每个会话只接纳一个活跃任务，第二次并发提交返回 409，用户刷新后决定是否重新发送。

## 权限与数据绑定

首批会话仅创建者本人可读写，同租户其他管理员或数据人员也不能读取会话内容。旧单轮任务继续采用原角色授权。会话任务经过旧 `/tasks` 列表、详情、SSE、停止接口时仍检查会话所有者，防止接口旁路。

每次操作重新加载账号和指标权限。有效计划、草稿或待执行候选有任何未授权指标时整体拒绝，不向模型发送该上下文，也不返回部分历史结果；提示使用当前权限新建问数。执行前、结果落库前及历史读取采用一致检查，权限中途撤销时不提交新上下文。

历史按轮次整体检查指标权限，不拆出一轮内仍获授权的指标；不可见轮次只返回安全占位。会话标题及摘要不能绕过对应轮次的权限检查。

Python 新增服务密钥保护的 context 元信息接口，由 Go 使用可信租户及角色调用，返回分析基准、目录摘要和不含凭据的数据绑定指纹。创建会话时固定绑定，读取和新增追问时重新核对；调用超时两秒或服务不可用时明确失败，不使用陈旧缓存。

数据绑定基于租户、角色、逻辑数据源、授权账号和显式 context_revision，不包含密码；密码轮换不改变语义绑定。context_revision 默认 1，授权视图或数据集语义变化时由运维递增。分析基准、目录、角色或绑定变化要求新建会话，防止历史计划在不同语义下静默重用。Python 执行入口再次核对绑定，模型和浏览器不能指定它。

SQL 仍由受信任目录编译，使用绑定参数、AST 白名单、授权视图和只读账号。沿用单次模型 20 秒、SQL 10 秒和 Go 重试预算，追问解析最多一次模型调用，默认复用现有 512 Token 计划额度，不添加内部循环重试。

## 接口与前端

- `POST /api/conversations` 创建空会话，返回 ID、version 和当前数据基准。
- `GET /api/conversations` 分页读取本人会话，首批每页 20 条。
- `GET /api/conversations/{id}` 返回当前版本、有效条件摘要、草稿及按轮次排列的可见任务。
- `POST /api/conversations/{id}/turns` 接收 request_id、expected_version、当前 question 和可选手动约束，返回 202 与任务 ID。
- `POST /api/conversations/{id}/discard-pending` 接收预期版本，取消当前草稿并返回新版本。

浏览器不提交 QueryPlan、PlanDelta、角色、租户、绑定或内部快照。Go worker 从存储读取可信快照交给 Python，响应中的候选计划和草稿都需验证绑定及完整指标权限。单轮结果协议 v2 继续复用，另附版本化的多轮修改信息。

前端按会话展示多轮消息和对应结果，侧栏保留旧单轮历史入口。发送后清空当前问题，沿用任务 SSE 更新结果并重新获取会话版本。显示当前条件、继承和修改摘要、待补充内容、Token 用量及停止按钮；409 提示刷新，不自动覆盖另一窗口的修改。刷新可恢复，但不自动重复提交问题。

## 独立多轮评测与交付

新增独立多轮题集，首批至少 30 个意图链，每链 3–6 轮，按意图链隔离开发与验收。同组改写不跨分区，不能将每一轮视为独立业务问题。包含替换、增加、移除、联合修改、澄清补答、初始缺条件、取消草稿、失败后继续、并发、重试、权限撤销和跨租户访问；至少十条链包含陌生追问。

每轮预先标注基准计划、应修改和应保留字段、预期草稿及终态；成功结果由原始 CSV 独立计算。报告每轮计划和结果正确率、整条链全部正确率、继承字段错误、条件遗漏或新增、应澄清却执行的次数及权限失败。错误、超时和未完成轮次保留在分母；未返回计划的失败标为不可观察。

在相同提交、数据和身份下，对照“无上下文逐句独立问数”和“受控多轮”，量化上下文补足了多少追问及完整链，而非比较 SQL 执行成功率。旧单轮冻结门禁及 90 题表达证据保留各自题集版本。

验证包括 Pydantic schema、Delta 应用及不可变字段、真实 MySQL 结果、真实 PostgreSQL 接纳和完成事务、重复 request_id、陈旧版本、停止与迟到结果、租约恢复、预算耗尽释放活跃任务、权限变化后历史和 SSE 不泄露，以及 React 类型检查、生产构建和浏览器多轮验收。

真实模型评测显式启用，串行三轮；每轮含重试最多 120 次模型请求，三轮最多 360 次，出站前执行硬预算。预算耗尽标记 incomplete；Token 未返回时保持未知。独立 Olist 只读复核与合成夹具报告分开，不修改运行服务。

分批提交已验证代码：先 Delta 与澄清协议，再持久化、任务和权限，再前端和独立多轮评测，最后实测证据与复现说明。新增迁移只在隔离测试数据库验证，云端部署单独执行。需求及技术方案确认后编码；代码与测试结果交付后再由用户人工验收。
