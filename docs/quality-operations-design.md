# 问数质量与线上运行：需求及技术方案

日期：2026-10-10。

状态：用户同意继续补齐与生产系统的差距，并选择云主机 + Docker Compose。本文是待人工确认的首批需求与技术方案；尚未实现评测平台、执行遥测或费用配额，未部署云账号。

## 目标与分批

以现有受限问数能力为边界，建立可重复的正确率评测、可定位的执行记录和真实部署验收。已有规则优先、QueryPlan、权限、SQL 编译和任务租约继续复用。

1. A 批：独立业务评测、逐次执行记录、租户运行统计与云主机验收手册。本文细化此批，确认后实现。
2. B 批：跨实例共享的模型调用、Token 与费用预算。单独确认调用前预留、失败用量不明、重试、价格版本和结算方案后实现。A 批记录用量，不宣称已经有费用硬上限。
3. C 批：已验证示例与反馈复核、多轮追问及分析能力扩展，按独立规格推进。

图表解耦继续按 [展示方案](chart-presentation-design.md) 单独交付，不将其作为评测和遥测的依赖。此次不扩展品类、同比环比或自由 SQL。

## A 批需求规格

### 独立业务评测

首批建设 120 条人工定义预期的问数案例；这是待建设数量，不计入当前已完成验证。

| 类别 | 数量 | 预期 |
| --- | ---: | --- |
| 支持范围内的常用表达 | 50 | 完整完成查询，覆盖六指标、日/月/州、筛选、排序、Top N |
| 支持范围内的陌生表达 | 25 | 按实际解析路径完成；不强制所有陌生表达必须调用模型 |
| 条件缺失、冲突及歧义 | 20 | 澄清或明确拒绝，不执行 SQL |
| 超出当前业务范围 | 15 | 明确说明能力边界，不删除条件后返回部分答案 |
| 权限与隔离 | 10 | 越权全部拦截；模型、SQL 与结果不得扩大权限 |

上述分类互斥。样本按类别分层分为开发集 60 条和独立验收集 60 条；每个具体问题及其改写属于同一分区，避免同义改写泄漏。显式标记要求规则命中的高频样本，并另设少量模型集成样本验证兜底链路。

每条案例包含 ID、类别、分区、问题、手动参数、服务端测试身份配置、分析基准、预期状态、人工标注业务条件、预期结果或错误类别、规则零调用要求。案例身份用于测试账号选择，不能作为浏览器可任意提交的租户/权限字段。

验收集不放入提示词、检索示例或规则调优素材。查看验收错误并据此修改实现后，该问题及同组改写转为回归集，补充新验收问题并发布新数据集版本；不得反复调优同一套题后称为独立准确率。

### 评测执行与判定

- 快速离线回归：固定的小型原始 CSV 夹具，覆盖 NULL、真实零、无数据、样本分母和排序。模型 mock 只验证契约，不生成真实模型准确率。
- 真实端到端：专用 PostgreSQL 测试账号、MySQL 授权视图，经过登录、任务创建、worker、Python 和 SQL 链路。数据与生产隔离，不修改日常账号权限。
- 黄金结果：独立从原始 CSV 构造事实并计算；评测代码不导入运行时解析器、目录公式或 SQL 编译器。允许复用现有独立核对算法，但扩展边界需要人工复核。
- 检查状态、时间区间、指标集合、维度、筛选、排序、Top N 和结果；只比较数字不足以判定问题解释正确。预期业务条件由人工定义，不从实际 QueryPlan 反推。
- 金额/计数精确一致；除法/均值沿用绝对误差 0.0001；NULL、样本数、排除数量、组键与业务排序独立比较。同义且语义等价的枚举条件允许归一化比较。
- 无数据是合法业务结果；与实际零分别判断。超时、供应商故障和执行失败在主指标中计为未正确完成，另列运行原因，不从分母删除。
- 真实模型评测显式启用，限制最大请求次数，默认串行；没有模型配置时标记未执行。不得将跳过、mock 成功或离线回归当成真实模型评测通过。

报告分别给出：支持问题正确完成率、已完成答案条件正确率、澄清/范围拒绝符合预期率、权限通过率、规则零调用符合率、运行失败率，以及按类别和解析来源的分项结果。

支持问题正确完成率 = 正确完成的支持问题数 / 全部支持问题数；已完成答案条件正确率 = 正确答案数 / 已完成支持问题数。后一指标必须同时显示分子、分母，不能用大量拒答抬高准确率。范围覆盖率另行记录，不混入支持问题准确率。

沿用总规格中的结果一致率 >=85% 目标，将此批主门槛明确为独立验收集中支持问题正确完成率 >=85%；权限泄漏为 0，明确澄清/拒绝样本不得执行 SQL，高频规则样本调用模型为 0。此门槛是提议验收条件，不是当前实测结果。120 条初版也不代表已完成总规格的 300+ 建设目标。

每份报告记录数据集版本、原始 CSV 哈希、代码 commit、语义目录及提示词版本、模型 ID、供应商配置标识、时间、用量、各样本结果。供应商未返回具体模型版本时标记不可确定；固定模型名称不等于供应商权重永远不变。

默认报告只输出案例 ID、判定、错误类别和统计；详细问题/SQL/结果通过显式选项写入本地忽略目录，不上传 CI 公共产物。认证凭据始终通过环境或交互输入，不放入案例与报告。

### 执行记录与运行统计

每次 worker 执行以 task_id + execution_version 关联独立 attempt 记录。一个任务的多个尝试均保留，不能只记录最终成功那次，也不能将每次尝试算成不同用户任务。

记录排队时间、本次开始/结束时间、规则解析、模型调用、计划校验、数据库连接、SQL 执行、结果规范化耗时；记录实际 parser、已发出的模型请求数、模型及版本标识、供应商返回的输入/输出/总 Token、组数、结果字节数、状态和错误类别。

未进入某阶段和无法观察到该阶段分别表示。未知用量必须为 NULL，并单列未知调用数；只在明确未调用模型时记录 0。费用价格表及预留尚未上线，因此首批不显示推算费用为已结算账单。

错误类别至少包括权限失效、需要澄清、能力不支持、模型配置/网络/超时/限流/认证/响应格式、SQL 超时/连接/结果超限、agent 不可达、平台持久化失败及用户停止。用户提示保持简洁，内部类别用于定位；原始供应商响应和异常文本不返回用户或直接写日志。

`GET /api/operations/summary?days=7` 提供本租户管理员可读的汇总，days 仅允许 1、7、30。租户来自会话，普通角色返回 403；接口不接受 tenant_id，不暴露问题、SQL、结果、账号明细及自由筛选。

汇总返回任务量及最终状态、规则/模型/未知解析数量、重试次数、各错误类别、已知 Token 和未知用量计数、排队及任务端到端 P50/P95、本次执行和各阶段 P50/P95；所有指标明确样本数和时间窗口。重试跨日分别按 attempt 开始时间统计；任务统计按创建时间统计，尚未结束的不参与结束耗时分位数。

运行成功与业务答案正确分开呈现。线上状态为 completed 只能说明执行完成，不能作为业务正确率；正确率来自独立评测或人工复核。

首批提供受保护 JSON 统计接口和可复制的运维查询方式，沿用现有工作台；后续管理页面可消费同一接口。

## 技术设计

### 数据库与协议

新增 `task_attempts` 表，包含租户、任务、execution_version、状态、时间和受限遥测字段；对 task_id + execution_version 建唯一约束，租户/任务关系通过复合约束或等效数据库约束保证。为 tenant_id + started_at 建索引，按租户与固定时间窗口汇总。

attempt 创建与 Claim 的租约抢占同事务提交；无法创建记录时不执行本次分析。完成、重试与停止记录分别幂等处理，禁止旧版本修改新版本的 attempt 或任务结果。旧 attempt 的合法末态遥测允许记录，不代表允许旧结果写回；迟到的 completed 不得覆盖 canceled/lease_expired。

worker 崩溃后，租约重抢时封存旧 attempt 为 lease_expired；缺失阶段/用量保持未知。停止先提交取消状态，再中断请求；取消后的结束遥测仅更新原 attempt 的受限字段。遥测结算失败输出安全错误记录并列为缺失，不凭空补零。当前 MySQL 查询可能继续到超时上限，首批保留这一明确边界。

Go 生成并传递任务/attempt 上下文，浏览器不能指定。Python 在内部响应中添加版本化 telemetry，成功、澄清和可捕获失败路径均覆盖。Go 限制字段、长度、非负耗时与 Token，核对上下文，仅接纳本次 attempt 数据。平台侧独立测量整次调用耗时；agent 失联时仍能保存平台侧结果。

旧任务结果不改写，v1/v2 展示保持兼容；历史任务没有 attempt 时显示无遥测，不重建虚假记录。新协议与旧 agent 混部署时缺失 telemetry 标记 unknown，不能阻止原有业务结果兼容读取。

采用下一个未占用的新增 SQL 迁移编号；若图表方案先占用 002，则本批使用后续编号。禁止改写 001 或任何已经应用的迁移。迁移账号执行 DDL，运行账号仅获新增表所需权限。

### 日志、保留与部署

Go/Python 输出结构化 JSON 日志，使用同一 task/attempt 关联。只包含安全 ID、阶段、耗时、状态和白名单错误码；不记录用户问题、SQL/参数、行数据、提示词、密钥、Cookie、DSN 或异常响应正文。模型名称/配置标识只来自可信配置，禁止把 endpoint 查询参数当标识。

首批复用 PostgreSQL 和容器日志，不新增常驻监控服务。attempt 默认保留 30 天，提供仅删除过期遥测的显式运维命令，分批清理且保留业务任务/事件。统计标记可用数据起点；已清理数据不参与历史汇总。配置 Docker 日志轮换，集中日志和告警接入留作真实云部署阶段。

确定使用云主机 + Docker Compose。复用现有 API/agent/web 镜像与 `deploy/compose.cloud.yaml`，补齐新表运行授权、迁移顺序、日志轮换、健康检查和验收操作。本地调试与云端采用相同协议；配置不依赖 Windows 绝对路径。

真实部署需要目标主机、域名/TLS、镜像仓库、数据库位置及资源规格。资料未提供时先完成手册与本地验证；不创建收费资源或默认选择云账号。实际资源操作另按用户提供的目标和授权落地。

## 验证与交付

| 项目 | 验收要求 |
| --- | --- |
| 评测器 | 无模型配置、未运行、超时、合法无数据、错误数值/条件/排序可区分；报告分母固定，退出码反映门槛失败 |
| 独立性 | 黄金计算不导入运行时公式；同义问题不跨开发/验收分区；提示词不含验收样本 |
| 真实链路 | 专用账号/数据库执行评测，记录真实模型请求和用量；mock 与实测报告明确分离 |
| 遥测 | 完成、澄清、模型失败、SQL 失败、连接中断、结果超限均有记录；未知不等于 0 |
| 任务一致性 | 真实 PostgreSQL 覆盖重复完成、重试、租约过期、停止、重启和迟到记录；无跨版本覆盖 |
| 汇总权限 | 两租户隔离，普通角色拒绝，管理员只看到本租户；汇总不返回问题/SQL/结果 |
| 统计 | 多次尝试与最终任务分别计算，时间窗口、未知计数和 P95 样本数可核对 |
| 隐私与保留 | 日志敏感字段检查通过；清理过期 attempt 不影响历史任务和 SSE 事件 |
| 兼容 | 原有 Go/Python 回归、TypeScript/构建通过；v1/v2 历史展示和无 telemetry 响应兼容 |
| 本地部署 | 新迁移、镜像、Compose、规则/模型查询及租户统计验证通过 |
| 云端实测 | TLS/Cookie、私网数据库、登录问数、SSE 续传、重启恢复、备份恢复、固定资源负载测试 |

CI 默认执行确定性离线评测器回归；真实 Olist/模型评测按显式开关在受控环境运行，缺失数据或凭据标记未执行。真实评测门槛作为发布验收，不能由 mock 测试代替。初次报告如未达标，交付失败分项与原因，不修改预期迎合实际实现。

简单问数 P95 <=30 秒沿用总规格目标，但必须报告模型、数据规模、资源、并发、缓存状态和窗口。50 活跃/100 排队仍是待压测验收额度；单次压测不证明 99.9% 持续可用。

需求及技术方案人工确认后，按评测、遥测与统计分批实现；每批通过相应验证后 commit，最后提交实际结果供代码/测试人工验收。所有尚未执行的云端、费用预算及 300+ 评测项目保留为未完成。
