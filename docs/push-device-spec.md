# 推送效果与设备分析规格

用户于 2026-10-18 确认业务与技术方案：Python / FastAPI / LangGraph / PostgreSQL / React；使用明确标注的模拟数据，设备 ID 直接生成，用户自定义时间，不限定为一周。本文是本次实施与验收依据。

## 能力

- 查询发送、受理、已确认到达、点击、失败、未知到达、平均到达时延及对应比率；按应用、设备厂商、实际通道、发送日期或月份分组和筛选。
- 查询指定时点的设备总量、有效、无效、未知设备；查询自定义期间的活跃、活跃有效设备。设备主键为应用与设备 ID，跨应用物理设备数不混为同一指标。
- 分析支持单期分组汇总、Top N 分组及组合汇总；比较两期同口径推送指标，选择下降最大的分组并核查发送量、已确认到达、点击、失败和时延。只作描述性核查，不声称因果归因。
- 结构化表单不调用模型；自然语言由严格协议解析，条件不足则澄清。自主分析复用模型选择注册工具、账本预算、图检查点、interrupt 和执行围栏。模型不能指定 SQL、表或数据源。

## 数据与时间

模拟数据覆盖发送区间 `[2026-04-01,2026-10-01)`，快照为 `2026-10-15T00:00:00+08:00`。字段与生成说明见数据包。主表包括应用、设备、权限历史、通道 Token 状态历史、应用活跃、逻辑投递、发送尝试和原始回执。固定种子生成，可复现；设备 ID 为随机业务标识形式，没有 IMEI、广告 ID 或可用 Token。

查询接受带时区的自定义 `[start,end_exclusive)`，支持小时、跨天、多月；发送批次查询与回执观察时长分别指定。设备存量使用独立 `as_of`，默认期末前一微秒；活跃期间独立由查询窗口决定。日期输入在前端转换为上海时区，不依赖服务器时区。请求超出已发布快照、未成熟观察窗口或未知维度不得静默返回完整结果。

发送量按逻辑投递去重，重试量另算。到达与点击按同一发送批次、发送后的观察时长统计；到达回执缺失为未知，不等于失败。点击/发送与点击/到达分别命名；后者分子取已确认到达且点击的交集。到达时延只基于有有效到达时间的样本。总体比率按总分子/总分母计算；零分母为无数据，禁止平均各组百分比。未知/缺样本不能按零参与下降排名。

设备在时点上权限 granted 且至少一个有效 Token 为有效；权限 denied 或所有 Token 明确 invalid 为无效；其余未知。有效、无效、未知互斥并覆盖该时点已注册设备。活跃以应用前台事件判断，不以推送点击代替。历史状态按有效区间读取，期末存量不按日累加。多行通道历史及活跃事件先按设备聚合，再计算设备指标。

## 安全与兼容

可信数据源显式绑定 `domain=push`、不可变数据摘要及带时区数据截止时间。每个租户/角色只读账号仅获该 schema 授权视图。新快照使用新 schema，拒绝覆盖。模型证据继续绑定数据/目录/代码/模型，派生指标依赖需全部授权，撤权后不能读取旧证据。

现有订单数据域只用于显式配置的历史兼容与回归；新项目首页、初始化、示例及文档以推送终态描述。历史 Olist 模型成绩不能作为推送评测成绩。此次不自动修改云端数据、切换生产服务或推送 Git 远端。

## 验收

1. 固定种子生成、导入完整性与重复/延迟回执去重；同一设备多应用、多通道、权限变化和缺回执点击。
2. PostgreSQL 真实只读视图执行与独立原始 JSONL/SQLite oracle 对齐；至少四个非固定周窗口、历史设备时点、零分母和时间边界。
3. 查询/工具/完成证据校验、指标撤权、数据绑定变化、未知执行、持久化恢复与已有回归。
4. 前端类型检查与构建，实际页面核验；飞书同步终态项目介绍与技术选型，明确模拟数据及验证范围。
5. 代码与验证记录提交 commit，保留用户原有 `.github/rulesets/master-pr-only.json` 修改。
