B 的运行时模型计数为 53，实际供应商请求为 52：一次 `input_limit` 在发送前停止。请求数来自停止发送进程后结算的 PG 原子计数，不把模型决策计数混称为实际发送次数。

## 失败与局限

- B `analysis-13-2`：查询后 `calculate` 参数错误，首次修正名额已使用，任务停止；3 次模型计数、1 次 SQL。未伪造 Top1 合计。
- B `analysis-19-2`：累计上下文达到输入上限，发送前停止；8 次模型计数、实际该末次未发送、1 次 SQL。另一种复杂 TopN 表达完成了 GMV、订单、整体客单价和占比核对，不能以该成功覆盖本次失败。
- C `analysis-37-1`：范围外题在模型请求收到 **503** 后按未知结果停止；SQL=0，保留预留，不自动重发，也没有把基础设施失败判为正确业务拒绝。故 C 虽完整支持任务 8/8，全任务行为并非 12/12。
- 无数据题均保留独立数据证据；不把空结果编造成完整的零金额分析。
- 完整 Olist 数据上的扩展 TopN 503 失败仍见 [ECS 验收记录](python-platform-ecs-validation.md)，本轮合成夹具成功不覆盖那条记录。
- 题集仍为 `draft`，未人工复核，只有 6 个开发意图组、一次重复；这些组已曝光。P95 在每组 12 个样本下就是最慢样本；没有真实并发负载或吞吐结论。
- 补充答案由评测器立即提供，延迟不包含人工响应时间。解释可读性、自由文本拒绝质量尚未人工评审。完整未曝光任务集对照及实际费用比较仍待执行。

当前可展示的工程价值是：有限工具、确定性数值与证据核对、失败不伪装成功、持久执行和可复核的对照过程。当前数据不足以支持“用了 ReAct / LangGraph 就比固定流程更好”；固定计划在本轮支持任务上完成更多、发出的请求更少，应作为后续选型的优先候选。
