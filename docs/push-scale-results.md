# 大规模推送样本实施记录

日期：2026-10-20。依据：[已确认的扩容方案](push-scale-technical-design.md)。本轮只处理本地模拟数据与隔离数据库，未切换线上数据源。

## 实现

生成器通过 `--devices`、`--deliveries` 指定目标数量，设备分布于三个模拟应用，大样本设备 ID 全局唯一。原有 600 条应用设备记录的小样本继续供快速回归，保留跨应用重复注册等既有测试。

大样本逐条写入 `.jsonl.gz`，不保留完整发送或回执列表，也不在内存中全量排序。设备状态只保留必要的小型索引。写完后独立重读全部文件，使用父子记录顺序合并验证发送尝试、回执关联与时间；同时核对计数、内容摘要、最近活跃时间及模板字段，重新计算按日、应用、厂商、通道和模板划分的核对值。

导入器同时支持 `.jsonl`、`.jsonl.gz`，逐行解压并 COPY。跨表关联、冲突去重键和历史区间在数据库内检查，失败回滚整个新 schema。生成器清单为未完成或内容摘要不一致时不发布。

发布前新增私有 `push_receipt_summary`，每条投递至多一行，保存到达、点击、过期的最早事件时间；重复回执不增加投递量，点击不补造到达时间。查询视图关联这个已归并结果，保留用户自选观察时长，不在每次查询中重新聚合全部原始回执。查询账号仍不能访问原始表或私有归并表。

## 本地文件

- `data/push-medium/`：2 万设备、100 万发送的分级验证样本。
- `data/push-large/`：20 万设备、1000 万发送的目标样本。
- 各目录的 `validation.json`：实际数量、内容摘要、生成耗时及峰值内存。
- `import-report.json`：导入阶段、实际数量、数据版本、数据库占用及导入内存。
- `query-report.json`：只读查询与独立核对结果、查询耗时、执行计划及工具场景。

大样本及本地数据库连接信息保存在忽略目录，不提交 Git。完整样本保留在本机，报告不包含密码或可用设备 Token。

## 验证方式

百万级样本先完成生成、导入与真实只读查询，再依据实测数据库占用和压缩文件大小外推目标规模：估计完整构建、数据库与写入日志约需 17.85 GB，另预留 8 GiB，当时可用约 39.61 GB，通过后才启动目标规模。

只读验证覆盖单日、七天、单月及全期的整体、通道、厂商、模板取数，应用与厂商联合筛选，设备存量、有效性及活跃数。发送、受理、到达、点击和比率与独立文件统计核对；设备数、物理设备去重、状态及活跃数也独立核对。实际查询继续受数据库 10 秒、客户端 15 秒上限约束。

专项程序还执行真实 A→B→C 查询依赖，运行开放分析的查询、比较和带引用报告工具，并检查超过 1000 组时拒绝返回完整结果。工具场景没有请求外部模型，不能证明真实模型理解与调查质量。

查询耗时为本机导入后的单次演练，包含已缓存的数据页；不是并发容量、冷启动或云端性能承诺。

## 实测结果

| 项目 | 百万级分级验证 | 千万级目标验证 |
| --- | ---: | ---: |
| 设备 | 20000 | 200000 |
| 逻辑发送 | 1000000 | 10000000 |
| 发送尝试 | 1060190 | 10605535 |
| 原始回执 | 762339 | 7662701 |
| 活跃事件 | 1074601 | 10806113 |
| 压缩文件大小 | 104615008 字节 | 1063794279 字节 |
| 生成耗时 | 48.141 秒 | 502.219 秒 |
| 生成进程峰值内存 | 42.61 MiB | 181.03 MiB |
| 数据库表及索引 | 908361728 字节 | 9113804800 字节 |

目标快照另有 260263 条权限历史、288394 条通道历史；包含 258718 条重复回执，以及 62146 条有点击但缺少到达回执的投递。全部为模拟数据。

千万级初次查询中，七天整体统计触发了原有 10 秒上限。实际执行计划表明宽发送表回读成本过高，因此增加覆盖指标字段的索引、为回执归并主键附带事件时间，并在独立导入事务提交后执行 VACUUM，标记数据页可见性；没有增加查询超时。最终 18 组查询通过，最慢 2.157 秒；全期整体统计返回发送量 10000000，设备独立核对为 200000。导入和索引维护合计 555.563 秒，导入进程峰值 56.18 MiB。

若导入由外部事务包裹，程序不会代替调用者提交；报告明确标记等待提交且尚未发布，不在事务内部执行 VACUUM。

最终后端完整回归：**480 passed，3 skipped，257.90 秒**。跳过项为两项缺少 `pg_dump/pg_restore` 的完整备份恢复测试，以及一项缺少完整 Olist 文件的独立核对；真实 PostgreSQL 推送测试已执行。源码与原始报告摘要见 [机器可读证据](evidence/push-scale-20261020.json)。

用户随后授权部署服务器；云端发布与验收另行记录，本节数值仅代表本地验证。
