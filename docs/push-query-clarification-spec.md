# 推送查询补充与任务记忆

## 已确认需求

自然语言查询需要补充时，用户在追问下方回答并继续当前任务，不必返回顶部重写问题。原问题、历次追问和回答可在刷新及历史任务中恢复；修改原问题明确创建新查询。

## 实现约定

- PostgreSQL 保存原问题（不覆盖）、有界追问/回答、补充版本和请求幂等键。浏览器只记住当前任务 ID；未提交的回答不属于任务记忆。
- `POST /api/tasks/{id}/answers` 只接受任务所有者对推送自然语言查询的补充，校验状态、版本、角色、指标权限和数据源绑定。相同请求标识和内容重复提交不产生新一轮；内容不同返回冲突。
- 每次补充由用户明确提交，最多 2 次，每次等待 24 小时。原问题和已提交的补充共同交给解析器生成受限计划；数据仍由授权只读 SQL 查询，不把历史文字视为查询事实。
- 第 0 轮保留现有查询回执；补充轮次使用独立回执，已完成回执可恢复，结果未知的模型调用不自动重发。取消、旧版本或过期任务不能继续。
- 兼容升级前已处于“需要补充”的推送查询；数据库变更为追加列和表，不修改旧查询回执。
- 这属于当前任务的上下文记忆，不是跨任务的个人偏好记忆或向量检索。分析任务继续使用原有 PostgreSQL 状态与 LangGraph 检查点。

## 验收

真实 PostgreSQL + 模拟模型 HTTP 验证同任务补充、两轮上下文、刷新恢复、幂等/冲突、权限和绑定、过期/取消、崩溃回执恢复；前端编译和实际界面验证。真实模型调用另受现有外部调用授权约束。
