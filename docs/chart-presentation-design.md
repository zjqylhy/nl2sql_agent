# 查询与展示解耦：需求及技术方案

日期：2026-10-10。

状态：用户已同意系统推荐默认图表、允许用户覆盖，并将 QueryPlan 与 ChartSpec 分离的方向。本文细化首批需求和技术方案，等待人工确认；尚未修改运行时代码。

## 问题与目标

当前 QueryResult 按维度硬编码图表：州为柱状图，日/月为折线图，整体为卡片。用户不能要求州折线图，也不能在结果页切换展示。Chart 在折线模式下还会自行按标签排序，可能改变 SQL 排名的展示顺序。

将“查什么数据”与“怎么展示数据”分别表达。QueryPlan 继续决定指标、时间、筛选、聚合、SQL 排序和 Top N；ChartSpec 只引用查询结果字段，决定图表类型及字段映射。修改展示复用已有结果，不执行新的分析 SQL，不调用 LLM，不创建新的问数任务。

## 首批需求

### 类型与默认选择

| 结果结构 | 系统默认 | 用户可选 |
| --- | --- | --- |
| 整体结果 | 数值卡片 | 卡片、表格 |
| 州分组 | 柱状图 | 柱状图、折线图、表格 |
| 日/月分组 | 折线图 | 柱状图、折线图、表格 |
| 日/月与州联合分组 | 按州拆分的折线图 | 按州拆分的柱状图、折线图、表格 |

不同指标继续分别绘图，保留各自单位与样本；表格展示全部已查询指标。没有明细时显示无数据提示；NULL 保持缺口、不转 0，真正的 0 正常展示。筛选条件、Top N 范围、口径、SQL 与参数不因切图而隐藏。

首批支持柱状图、折线图、表格、卡片，不包含饼图、散点、地图、堆叠、双轴和任意图表代码。无分组的整体值要求折线图时先澄清，不猜测或增加时间分组。

### 用户指定与覆盖

- 自然语言支持明确的“用折线图展示”“绘制柱状图”“以表格展示”“用数值卡片展示”等表达。常见表达用规则提取，业务问题原本可走规则时仍为 0 Token。
- 展示信息先从问题中单独提取，清理后的业务问题进入已有 QueryPlan 解析。保留原问题作为任务标题及审计输入。
- 模型只补齐业务查询，不决定图表代码。明确图表要求不能被删掉或被默认图表替代；类型冲突、未知展示指令或与数据结构不兼容时先澄清。
- 完成任务的结果页提供类型切换和“恢复默认”。页面手动选择优先于问题指定；恢复默认清除手动覆盖，回到问题指定的类型，无指定则系统推荐。
- 手动选择保存到当前任务，刷新页面和打开该历史任务仍有效。保存失败保留先前已保存的配置并提示失败。
- 类型切换不改变指标、分组、筛选、排序、Top N 或样本。改变这些业务条件仍是新问数任务。

### 字段映射与展示顺序

首批字段映射由结果结构确定：单维度为横轴；联合维度优先日/月作为横轴、州作为系列；纵轴为已选指标，每指标单独图表。首批不开放轴/系列编辑器，ChartSpec 仍记录映射供后续扩展。

所有图表保留 SQL 返回的横轴首次出现顺序，禁止因选择折线图再次按标签排序。默认州查询因此是州代码顺序，显式 GMV 排名则是排名顺序。联合分组按横轴标签对齐各州序列，缺少的组合使用 NULL，不伪造新日期或订单。

州折线图显示“州为分类维度，连线不表示时间趋势”，并说明当前展示顺序。日期/月份是时间维度。转换图表不会把分类字段解释成连续日期，也不重新求和或平均 SQL 已聚合的指标。

## 技术方案

### 独立协议

保持 QueryPlan 原 schema，不加入图表字段；SQL 编译器不读取 ChartSpec。新增严格、版本化的 ChartSpec，未知字段及未查询的字段拒绝。

```json
{
  "version": 1,
  "type": "line",
  "x": {"field": "state", "type": "nominal"},
  "measures": ["gmv", "orders"],
  "series": null,
  "order": "result"
}
```

type 仅允许 card/bar/line/table；x 与 series 只能是结果内的维度，measures 必须是已查询且已授权的指标。整体结果 x/series 为 null。时间字段 type 为 temporal，州为 nominal；这些类型来自服务端已发布定义。客户端与模型不能提交表名、表达式、JS、外部数据 URL 或渲染器配置。

新结果在 result_version=2 下增加可选 chart_spec 与展示来源（question/default），已有字段保持兼容。无 chart_spec 的 v2 历史按原结果结构生成默认配置；v1 旧单指标历史继续原展示，本批不扩展其编辑能力，不批量改写历史结果。

### Python：提取偏好与构造配置

新增 presentation 模块，独立完成展示指令提取、冲突检查、结果结构校验和 ChartSpec 构造。

请求流程：内部鉴权与数据源授权 → 提取展示指令 → 已有规则/模型 QueryPlan 解析 → 校验展示类型与计划结构 → 全指标授权与 SQL 执行 → 结果规范化并附加 ChartSpec。

常见图表指令完整提取后才消费对应文本。业务否定、排序、金额、状态等继续交由已有解析器验证；不得用宽泛文本删除把未知业务条件误当作展示要求。模型收到清理后的问题，并继续受原有明确条件约束。没有新的展示模型调用、重试或预算。

### Go / PostgreSQL：保存手动偏好

任务的查询结果 JSON 保存生成时的 ChartSpec。手动覆盖单独存入 tasks.presentation JSONB，默认 NULL，通过新增迁移 002 实现；不修改已有迁移或重新执行问数。

新增 PATCH /api/tasks/{id}/presentation，body 只允许 type=auto/card/bar/line/table。auto 清除覆盖，其他值由服务端根据当前结果构造并验证完整配置，返回更新后的任务。Task 增加可选 presentation 字段。

接口复用账号会话、Origin 同源检查、任务所属用户/租户隔离与全部指标权限检查；只允许 completed 的任务，查询中/失败/澄清任务不可编辑。撤权后读取或更新同样返回不可访问。UPDATE 条件包含所属用户、租户与任务状态；显示配置不能改变执行版本、任务状态、结果或 outbox。

同一账号的多个页面按最后成功保存的配置生效，不引入协同编辑。GET 历史返回该配置；服务端不信任客户端传入的轴、指标或系列。云端最小运行身份只需既有 tasks 更新权限，迁移由独立管理身份执行。

### React：渲染与交互

QueryResult 优先读取任务的手动 presentation，其次 result.chart_spec，最后根据已有结果生成默认配置。结果页显示当前图表类型和兼容类型的切换控件。

独立的纯函数根据 ChartSpec 与数据构造系列和标签，Chart 只负责渲染，不再通过 line 类型推断日期或重新排序。首次出现的标签顺序稳定；多系列对齐不把缺失值变成零。表格模式显示明细，卡片只适用整体结果。数值精度、单位和指标级样本沿用现有协议。

前端发送类型更新不创建任务，也不访问 Python。保存成功后采用返回的配置；保存失败恢复先前配置并展示提示。历史无新增字段时兼容渲染。已有 ECharts 支持柱状/折线，本批无需新图表平台或依赖。

### 发布

本地及云端复用已有 Go/Python/React 镜像。发布前先执行新增平台迁移，再更新 API/agent/web；配置无新增凭据。旧 API/前端忽略新增可选字段，旧结果可正常读取。未在云账号部署不得称为云验收完成。

## 验证与验收

| 场景 | 预期 |
| --- | --- |
| 本月 GMV 按州统计，用折线图展示 | 同默认柱状问题的 QueryPlan、SQL、参数及数值；规则 0 Token，州为分类横轴 |
| 本月 GMV 按州排名，取前 5 名，用折线图展示 | 保留 Top 5 和 GMV 排名顺序；不重新按州代码排列，不计算全范围合计 |
| 最近 6 个月 GMV 和客单价按月统计，用柱状图展示 | 两指标分别柱状图，原月份与样本不变 |
| 结果页从柱状图切为折线图/表格 | 当前任务 ID 和结果不变，不调用 Python/LLM、不创建 outbox；刷新保留手动配置 |
| 恢复默认 | 清除覆盖，恢复问题指定的类型或系统推荐 |
| 整体 GMV 要折线、同时指定两种类型、未知图表 | 澄清，不静默换图或执行部分问题 |
| 多指标撤权、跨租户更新展示 | 不可读取或修改，保留现有权限边界 |
| 旧 v2 无 chart_spec / 旧 v1 | 前者生成默认且可切换；后者保持原展示，不迁移历史 JSON |

Python 测试验证展示提取不改变业务约束、规则零模型调用、类型适配、schema 与未知字段拒绝。Go 真实 PostgreSQL 测试覆盖迁移、偏好持久化、恢复、权限撤销和跨用户隔离。前端验证图表切换、数据不变、排名顺序、NULL、联合序列、保存失败与刷新回查；浏览器截图核对图表效果，生产构建和本地 Compose 发布验证。

代码验证后提交 commit，提供具体实现与测试结果进行人工验收。
