# 需求规格 v1.0

状态：2026-10-09 已经用户确认需求、指标口径、异常处理和技术方案。来源：https://my.feishu.cn/wiki/FfymwxyGTiZfNAkLxqQcrftKnNc ，本规格中的确认项优先于原 PRD。

## 产品与范围

求职展示项目，按可上线运行的系统交付。真实多租户，由管理员建立租户和账号；运营问数、数据人员维护口径、租户管理员管理权限。首版使用 Olist 历史真实数据；TPC-H 只补充 SQL 评测。P1 包含画布、代码沙箱、定时推送、缓存，P2 包含跨源分析。

## 业务规则

展示可配置的分析基准日期，相对时间据此计算。显式日期按输入处理。默认本月环比比较相同已过去天数，月长不一致时缩短至双方都有的日期；时间区间为左闭右开。Olist 无时区时间按数据当地墙上时间存储，不擅自转换为中国时间；平台审计使用 UTC。

所有指标按订单创建时间筛选。GMV 为排除 canceled/unavailable 订单后的商品金额，不含运费，币种 BRL。订单量为同范围去重有效订单数；客单价为 GMV/有效订单量。取消率为 canceled 数/全部创建订单数，unavailable 单列。平均交付时长仅计已交付、时间有效的订单，单位天。平均评分每单保留一条有效评价；重复评价按创建时间、回答时间、review_id 确定稳定排序。无数据与实际零区分，显示有效样本、排除数量。商品、支付、评价先按订单聚合，再关联，禁止金额倍增。

归因为变化贡献拆解。总量按维度差额解释；均值/比例需处理权重变化。不同维度的贡献不能相加。业务原因仅为待验证假设，所有数值结论引用 SQL 与结果证据。简单问数先给答案，按需生成报告；归因/报告请求自动成报告。

## 异常与权限

歧义先澄清，不静默选口径；无数据不当零；部分失败禁止推导依赖缺失结果的结论。失败节点最多追加两次重试，任务有时间、调用、Token 与成本上限；越权不重试。用户停止取消后续执行并保留已有结果；停止的任务不自动恢复。等待澄清/人工输入释放执行名额；人工回填重新校验，沉淀口径/模板进入草稿审核。执行、恢复、历史查看、导出均重新检查权限。租户、账号、报告、SQL、事件均隔离。

## 技术架构

React/TypeScript/ECharts；Go 业务 API；Python/FastAPI/LangGraph；Celery/Redis；PostgreSQL 元数据/checkpoint；MySQL 分析；S3 兼容报告存储。Windows Docker Compose 开发，Linux 容器上线。元数据采用 PostgreSQL 是已确认的 PRD 调整。SQL AST、表/列/函数白名单、只读账号、受控视图、超时/结果/并发限制。LLM 只生成结构化意图/计划和文字，指标计算由受控程序执行。

任务创建与 outbox 同事务，事件持久化后 SSE 推送；投递幂等、租约和执行版本防止旧 worker 覆盖。执行预算在重投递时不清零。日志不得记录密码、DSN、模型密钥；服务仅通过内部网络访问执行端。

## 验收

独立 SQL 验收集结果一致率 >=85%，浮点误差、排序、NULL 有明确规则；训练/提示词示例不能混入验收集。300+ 是建设目标，52 条原素材不能宣称完成。黄金指标、贡献计算和报告数字必须一致。两个租户及角色越权全部拦截。测试停止、重启、重复投递、SSE 续传、预算耗尽、备份恢复。

在固定模型、数据规模、缓存状态与部署资源下测试：简单问数 P95<=30s，复杂归因<=90s，报告<=180s。50 活跃任务、队列 100；同用户仅一个执行任务。运行失败与答案错误分别统计。99.9% 为持续运营目标，需要多实例和数据库高可用，不能由单次功能测试证明。65%->80% 等改善数字须实测后才能用于简历。

## 里程碑

M1：骨架、鉴权租户、Olist 导入、六个指标、安全问数和基础工作台。M2：Planner/Reviewer、归因、多轮、队列/checkpoint/恢复、SSE。M3：管理端、人工介入、导出、评测扩充、性能与线上部署验收。

M1 的受限 NL2SQL 采用“结构化意图 -> 已发布指标 SQL 编译”，覆盖六个指标及地区维度，不开放任意 SQL。M2 扩展受控计划与下钻。M1 持久化任务/事件采用后台 outbox 执行，M2 替换调度为 Celery 并增加图节点 checkpoint；M1 不宣称具备完整断点恢复。

## 已确认变更：规则优先、LLM 兜底

2026-10-10 用户提出并确认：高频、简单问题若能通过规则解析，应跳过 LLM 节省成本；LLM 作为兜底。以下行为已实现，代码和测试待用户人工验收。

- 配置模型密钥后仍先尝试规则。规则完整、唯一地识别指标、时间、分组和筛选时，直接进入统一校验与 SQL 编译，标记 rules、Token 为 0。
- 首批规则覆盖现有六指标、日/周/月与显式日期区间、巴西州分组和州代码筛选。规则命中要求覆盖有业务含义的表达，不能只找到指标和时间就忽略未知维度或筛选。
- 对支持范围内的陌生表达，规则未命中且模型可用时调用 LLM，例如“本月 GMV，只看圣保罗州”；模型仍只返回结构化意图。模型未配置时返回澄清。
- 缺少必要条件、多个指标/时间冲突、手动参数与问题冲突时直接澄清。明确超出 M1 范围、越权、非法地区代码或无效日期时拒绝或澄清，不触发 LLM。
- 手动选择的参数是约束。规则不能完整解析剩余表达时可触发 LLM，但模型不能覆盖手动选择，冲突必须澄清。
- LLM 失败、超时或返回无效结构时明确失败；模型要求澄清时不执行 SQL。继续遵守任务已有的有限重试预算，不增加额外模型重试循环。
- 所有解析路径共用权限、时间范围、指标口径、SQL AST 和数据库只读限制。界面按实际执行路径显示规则解析或模型解析，已有任务结果保留原记录。

## 已同意方向：语义层与可组合查询

2026-10-10 用户确认了演进方向及第一阶段需求和技术方案，见 [语义查询规格](semantic-query-design.md)。第一阶段已实现：一次 1–3 个指标，州/日/月及最多两个联合维度，最近 1–12 月，州/状态/订单商品金额筛选，排序和 Top N。多个明确指标可组合查询，替代前述单指标限制；歧义仍澄清。规则与模型共用 QueryPlan、版本化语义目录和受控 SQL 编译器。多指标权限整体校验，兼容旧历史结果。代码和测试待用户人工验收；受控 SQL Agent、跨表关联和比较分析尚未实现。
