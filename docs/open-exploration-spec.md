# 开放式探索分析规格与技术方案

日期：2026-10-19。

状态：用户已确认首版覆盖当前推送/设备数据域，并进一步明确项目统一只有“明确条件取数”和“开放任务分析”两种跑数类型。原固定汇总、Top N、两期比较等能力归入明确条件取数，不保留独立的第三类固定分析。以下修订技术方案待用户确认，尚未实施。代码与测试完成后另行人工验收。

## 1. 现状与问题

- `agent/runtime/push_analysis.py` 的 `PushSpec.goal` 仅支持 `push_summary`、`device_summary`、`compare_push`；比较必须预先给定维度、排名指标和 N。
- `agent/runtime/push_tools.py` 要求查询计划完全属于 `plans(spec)`，不能根据结果增加维度或缩小样本范围。
- 比较与完成校验依赖固定规格和下降排名，无法表达“先确认下降是否存在，再选择调查方向”。
- 推送决策提示只提供证据引用、计划与行数，未提供指标观测值，模型不能据此选择下一步。
- 前端的自然语言入口创建单次查询任务，工具分析入口主要接受固定表单；开放问题缺少对应入口。

现有 LangGraph 循环、受控 SQL 编译器、账本、持久化证据、预算、检查点与权限校验可以复用。

## 2. 需求与交互

### 2.1 用户入口

产品统一只有两种跑数类型：

| 类型 | 用户给出的内容 | 系统职责 | 例子 |
| --- | --- | --- | --- |
| 明确条件取数（`query`） | 可以明确翻译为指标、期间、筛选、分组、排序或比较规则的请求 | 解析条件，编译受控 SQL，执行必要查询与确定性计算，返回结果 | “查询 7 月 app_1 各厂商的发送量和点击/发送率”；“比较 6、7 月各厂商点击率，列出下降最多的 3 组” |
| 开放任务分析（`analysis`） | 业务问题、调查目标与可探索边界 | 根据证据规划查询、验证线索、选择下钻，再整理解释与待验证假设 | “最近点击率下降，分析一下原因” |

表单与自然语言是明确条件取数的两种输入方式，不是两种跑数类型。推送/设备是数据粒度，汇总/Top N/两期比较是取数操作，都不再作为独立的业务任务类型。

取数可能需要多条 SQL 和后置计算，例如两个期间分别查询后比较，不能把“是否只执行一条 SQL”作为两类任务的区别。区别在于系统是否需要根据查询结果自主决定后续调查内容。

旧 `PushSpec` 的明确查询条件并入取数规格；原固定分析入口与新建执行分支归并到明确条件取数。保留历史记录的读取和已有问数会话能力，不以兼容名义保留第三种新建任务类型。

用户只需定义问题与分析边界，不必预先指定调查维度、Top N 或工具顺序。探索在已发布语义目录内进行。

### 2.2 澄清与边界确认

首次查询前明确以下条件；问题已明确提供的条件不重复追问：

1. 目标指标，区分点击/发送率与点击/到达率。
2. 可探索的时间范围；分析下降等变化问题时，还需当前期和基期。使用历史数据基准解释相对时间，展示明确日期与上海时区。
3. 推送回执观察时长，进行两期比较时保持一致。
4. 应用与其他业务筛选范围，允许用户明确选择全部授权应用。

缺少条件时集中追问，沿用最多两轮补充与 24 小时等待规则。可提出具体候选范围供用户确认；未经确认不静默补日期、选择分母、截断范围或采用默认观察时长。探索边界作为版本化规格持久保存；用户补充即表示确认其中明确给出的边界。

应用数据库中的数据截止只表示可查询边界，不表示发送样本实际覆盖该日期。先校验数据边界与观察成熟性，再根据查询结果识别无样本；当前模拟数据实际发送覆盖 2026 年 4—9 月。

### 2.3 自主调查

确认边界后，助手可以自行：

- 核查整体变化，必要时查看日/月趋势，验证“下降”这个前提。
- 从应用、厂商、实际通道等维度选择调查方向。
- 同时检查目标比率的分子、分母与已授权辅助指标。
- 根据已取得的异常分组证据缩小范围，再查询联合维度或趋势。
- 调整调查计划，记录已核查、未核查和无法核查的假设。
- 在证据足够或预算不足时停止；不强制执行固定维度序列或下降 Top N。

设备指标可独立探索，作为推送分析的辅助证据时，必须单独记录统计粒度与设备状态时点。设备存量不按日相加；设备样本与推送消息样本不连接成新的比率，也不能据此声称设备状态导致点击率变化。

### 2.4 最终交付

报告展示：问题与边界、整体变化、已核实的统计解释、关键证据、待验证假设、下一步建议及调查限制。

- 数字、排名和贡献由代码计算，结论引用具体证据与分组。
- 明确区分观察事实、统计贡献和业务假设。统计贡献不等于因果。
- 缺少文案、策略调整、实验、用户群或版本数据时，说明无法验证，不编造这些维度。
- 未发现下降时明确纠正问题前提；无样本、样本不足与指标实际为零分别表达。
- 展示调查步骤的简短依据和结果，不展示模型隐藏推理。
- 预算终止时交付已有证据与未完成项，明确“调查未完成”。

## 3. 技术方案（待确认）

### 3.1 探索规格与执行步骤分离

业务执行统一使用 `query` / `analysis` 两种模式；两类模式分别保存“明确查询规格”和“探索边界规格”。这是两种约束模型，不是增加业务任务类型。

- 明确查询规格保存已明确的指标、期间、筛选、分组、排序、Top N、比较和展示要求；复用底层 `PushPlan`，按操作组合生成受控查询与确定性计算。旧 `PushSpec` 不再作为新建任务的固定目标协议；汇总、Top N、两期比较的完成校验迁入取数执行路径。
- 探索边界规格（`ExplorationSpec`）保存用户目标文本、目标指标、可探索期间、观察时长、固定筛选、可调查维度、允许的辅助指标、设备状态时点（如适用）和已确认假设。只有需要比较的问题才要求基期，不能把所有开放任务强制变成两期下降分析。

开放目标使用统一的探索模式，不再把每一种业务问题映射成一个固定任务类型。规划与工具动作允许改变，已经确认的用户边界不可改变。

明确条件取数统一进入查询任务路径；开放任务分析复用 `/api/analysis-runs`、Worker 和现有 LangGraph。调整输入类型、规格加载、指标依赖校验、协议版本与数据绑定，避免继续接受旧 `PushSpec.goal` 创建第三类任务。已有旧分析任务保留授权读取；切换后尚未完成的旧协议任务不按新协议恢复，明确提示重新创建，既有回执和记录保留。

明确条件取数解析完成后按确定流程执行，不进入逐轮规划调查；自然语言解析仍可按规则优先、模型兜底执行。开放任务分析使用自主策略。移除面向用户的 `fixed` / `adaptive` 分析模式选择；配置未启用自主策略时明确提示开放分析不可用，明确取数仍可用。

### 3.1.1 流程变化

旧流程：输入 → 匹配固定 `goal` → 补齐规定的查询字段 → 生成固定规格 → 在规格限定的动作集合内执行 → 满足该 `goal` 的证据模板 → 输出。

旧 `adaptive` 模式虽然可由模型选择下一动作，但允许查询的条件和完成目标仍由固定规格锁定；这与开放探索不同。

新明确条件取数：表单或自然语言 → 澄清明确查询条件 → 编译查询/比较等操作 → 执行 SQL 与确定性计算 → 返回结果。结果不会触发未经用户请求的额外调查。

新开放任务分析：业务问题 → 澄清目标与探索边界 → 制定初步调查计划 → 选择查询/计算工具 → 获取并检查真实观测 → 更新线索与计划 → 继续下钻或换方向 → 核验证据与停止条件 → 输出解释、假设和未完成项。

| 流程环节 | 原预定义分析 | 新开放任务分析 |
| --- | --- | --- |
| 解析问题 | 必须映射到支持的 `goal`，不支持则澄清/拒绝 | 保留开放目标文本，解析出权限与分析边界 |
| 澄清内容 | 预定动作所需的维度、排名指标和 N 等 | 目标口径、时间、业务范围、观察时长；调查维度由助手选择 |
| 计划与观测 | 完成步骤受固定规格限制，推送提示未提供实际指标值 | 模型读取有界观测与预算，每轮更新调查计划 |
| 下一条查询 | 只能等于固定规格中的查询计划 | 可以在边界内换维度、缩小异常分组或检查辅助指标 |
| 计算 | 预设比较、下降排名与汇总 | 按需要调用比较、趋势汇总、贡献拆解等通用能力 |
| 验证重点 | 查询是否等于规格，证据链是否满足固定模板 | 查询是否在边界内、下钻来源是否真实、每条声明是否有对应证据 |
| 完成条件 | 达成固定目标的证据模板 | 完成声明的调查范围，或有证据地否定前提/说明能力缺失；预算不足标记未完成 |
| 输出 | 查询结果与规定的核查报告 | 观察事实、统计解释、待验证业务假设、后续建议及调查限制 |

指标口径、SQL 只读围栏、授权、审计、预算与检查点仍由代码约束。开放的是调查路径，不是 SQL 权限。

### 3.2 注册工具与范围校验

复用查询和口径工具，为探索增加通用的比较、贡献拆解和报告完成协议。执行仍为单 Agent 每轮选择一个动作。

| 工具能力 | 作用与校验 |
| --- | --- |
| 查询指标 | 使用现有 `PushPlan` 与只读编译器；指标、时间、观察窗口、维度和筛选均受探索边界约束 |
| 比较证据 | 接受本任务两份查询引用；校验指标、分组、筛选与观察时长一致，仅期间不同 |
| 拆解比率变化 | 从完整互斥分组的分子/分母计算组内变化、结构变化及进入/退出样本贡献 |
| 完成报告 | 验证整体比较和声明依赖的证据；按确定性模板生成数值事实，业务假设独立呈现 |
| 请求补充 | 仅在确需用户补充边界时触发，不让用户为每次常规下钻确认 |

查询必须位于已确认期间内；细分时间窗口显式记录，不能拿不同窗口充当完整两期比较。子组比较沿用相同筛选和观察时长。首版要求两期等长、不重叠，避免把时长差异当成量的下降；不等长需求先澄清。

下钻筛选只能增加约束，不能删除、替换或放宽用户筛选。子组筛选须引用当前任务完整父查询中真实存在的分组；对 `in`/`not_in` 使用集合语义检查，不能依靠字符串包含或只检查字段名。父证据、子查询与比较证据均保留来源引用。

新增辅助指标必须属于规格允许集合且通过现有依赖权限校验；每个查询和派生产物的 `metrics_used` 继续进入账本与历史读取授权。模型不能指定表、数据源、SQL 或新公式。

每次 SQL 继续最多两个联合维度、1000 组；超过时不得将截断数据用于总体或贡献结论。

### 3.3 比率变化的统计解释

先区分两件事：每一组自身的点击率是否下降，以及发送量是否更多地分配给本来就低点击率的组。两者都可能使整体点击率下降。

以下为解释方法的假设样本，指标为点击/发送率，不是当前数据库查询结果：

| 通道 | 基期发送量 | 基期点击量 | 基期点击率 | 当前发送量 | 当前点击量 | 当前点击率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| A | 800 | 80 | 10% | 200 | 20 | 10% |
| B | 200 | 4 | 2% | 800 | 16 | 2% |
| 整体 | 1000 | 84 | 8.4% | 1000 | 36 | 3.6% |

两个通道的点击率都没变，但发送量从高点击率的 A 转向低点击率的 B，整体因此下降 4.8 个百分点。这叫结构变化；如果只看各组点击率下降排名，会漏掉这个解释。

相反，如果发送占比仍是 A 80%、B 20%，A 点击率从 10% 降到 5%，B 保持 2%，整体就从 8.4% 降到 4.4%；下降的 4 个百分点全部来自组内变化。

两件事同时变化时，先改占比再改组比率，与先改组比率再改占比，分配到两项的贡献会不同。本方案采用两种顺序取平均的对称拆解，作为固定统计口径；总贡献与整体变化严格对齐。它解释数值变化如何组成，不证明某项业务动作导致了下降。

这是一项按需使用的计算工具，只在目标为比率变化且证据满足条件时调用，不是所有开放任务必须执行的固定流程。

总体比率使用总分子/总分母，禁止对组比率直接平均。对于两期都存在的组，令 `r` 为比率（0—1）、`w` 为该组分母占本期总分母的权重：

- 组内变化贡献：`(w0 + w1) / 2 × (r1 - r0)`。
- 结构变化贡献：`(r0 + r1) / 2 × (w1 - w0)`。
- 仅当前期有分母的组：单列进入贡献 `w1 × r1`。
- 仅基期有分母的组：单列退出贡献 `-w0 × r0`。

各项乘以 100 后以百分点展示，总和须与总体百分点变化一致。新出现或消失组不伪造缺失期的组比率。整体任一期分母为零时，不生成可比较贡献。

拆解必须基于同口径、无截断、覆盖整体的互斥分组；以分子/分母合计核对整体证据，不满足即拒绝声称完整解释。不同维度分别解释同一次变化，贡献不可跨维度累加。样本不足按明确展示的规则提示，首版不宣称显著性或因果效应。

点击/发送率与点击/到达率使用各自的已发布分子分母。缺到达回执的点击单列，不能假定“到达率 × 点击/到达率 = 点击/发送率”。

总量指标支持分组差额贡献；设备存量仅比较指定时点。平均时延首版仅作分组与样本核查，不自动套用比率拆解公式。

### 3.4 让模型依据实际观测规划

为推送证据提供有界观测摘要：总量与分子分母、两期变化、关键异常分组、无样本/未知情况、覆盖范围、可用引用与剩余预算。

模型可以从摘要选择下一步；完整结果仍由工具读取和校验。摘要裁剪必须标记，仅摘要前几组不能代表完整候选。最终贡献使用完整结果计算。保持现有单次 6000 输入预留上界，优先压缩计划重复字段和证据展示，不截断用户筛选或改变原始证据。

模型提交的数值发现改为结构化“事实类型 + 证据引用 + 分组”，显示文字与数字由代码生成。自由文本仅用于明确标注的待验证业务假设与后续建议；不将模型生成的数字写入已核实事实。报告完成检查校验引用属于本任务，并检查支持该类事实的产物类型和覆盖范围。

### 3.5 预算、停止与恢复

首版沿用现有上限：模型 10 次、工具 12 次、SQL 6 次、活跃执行 180 秒及已配置 Token/费用限制，不自动提高线上预算。

利用一次 `day + 调查维度` 查询的完整分子分母，可同时生成总体、趋势与该维度的汇总，减少重复 SQL。两期调查两次 SQL，异常子组两期补查两次 SQL；规划仍可根据证据选择其他合法路径。

计划应为必要计算与报告预留步骤。变化分析正常完成至少具备整体两期核查和一条已验证调查路径；其他开放任务按目标校验声明依赖的证据，不强制套用两期模板。前提不成立、整体无样本或能力缺失时允许有证据地终止。完成表示已完成报告声明的调查范围，不表示所有可能原因已经排除。

预算不足无法继续时，使用已有授权证据确定性整理未完成报告，不再发起模型或 SQL。复用 `failed` 状态并显示 `completeness=partial` 与终止原因，不新增“成功完成”的伪状态。取消保持 `canceled`；调用未知保留未知状态与预留，不为生成报告重发。撤权或绑定变化时按既有规则阻止证据读取。

纯计算产物同样记入操作账本；确定性终止整理通过独立、幂等的本地收尾路径保存，不绕过执行围栏。恢复复用持久回执，沿用租约、执行版本、预算冻结与取消规则。

### 3.6 前端与兼容

在 `PushWorkspace` 只展示“明确条件取数”和“开放任务分析”两个任务入口；表单/自然语言在明确取数入口内部切换。原“工具分析与两期核查”独立入口取消，其能力纳入明确取数。

开放分析包含问题输入、边界补充、调查过程、证据和探索报告；提交到分析 API，不能送入单次自然语言计划解析后被误判为汇总。明确取数的问题由开放分析入口提交时，可提示并经用户选择切换；不让模型静默改变用户所选跑数类型。

展示整体变化、每个调查维度的解释、下钻链路、业务假设、未完成项与剩余限制；证据可展开查看 SQL、参数和口径。原有 `Evidence` 保持历史结果兼容，探索报告使用独立组件。

首版探索使用独立分析任务；不在本次将探索产物强行接入现有查询消息树。执行中的条件补充继续复用分析任务；完成后用户可带明确边界新建探索。

## 4. 验收标准

1. “最近点击率下降，分析一下原因”在缺少口径、两期、观察窗口或应用范围时集中追问，不运行 SQL；补充后在同一任务继续。
2. 构造“各组比率稳定，但流量转向低比率组”的独立样本，正确识别结构变化；组内变化、混合变化、新组/退出组也与独立计算一致。
3. 两条不同的模拟模型决策路径可在同一边界内查询不同维度和下钻，说明探索过程不被固定模板锁死；每一步依据可见观测值。
4. 数据未下降、零分母、缺回执点击、少样本、未知分组、无数据、超行数和不等长区间正确处理；不同维度贡献不能加总。
5. 越界时间、改变观察时长、放宽筛选、伪造父组/证据、未授权指标与自造数字均被拒绝；设备与消息粒度不可混用。
6. PostgreSQL 真实只读视图、API/Worker、LangGraph 与账本端到端验证，覆盖澄清恢复、重复投递、预算终止、取消、撤权及数据绑定变化。
7. 前端完成类型检查、构建与浏览器交互验证；新建任务只允许明确取数/开放分析两类，表单与自然语言取数、Top N 与两期比较归并验证通过；旧结果仍可授权读取，旧 `PushSpec` 不得新建或恢复为第三类执行路径。
8. 模拟模型测试只证明协议与流程。真实模型需固定题单和请求上限后另行记录结果，不以模拟测试宣称真实开放探索效果。
9. 实施完成后记录验证范围、失败/跳过项与剩余限制，提交代码 commit，再由用户确认代码与测试结果。
