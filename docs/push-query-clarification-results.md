# 推送查询补充验收

## 本地验证

2026-10-18：完整测试 **384 passed，零跳过，148.90 秒**，其中新增补充链路测试 11 项。真实 PostgreSQL 验证任务、迁移、只读查询、幂等/版本冲突、两轮上下文、24 小时过期、取消、归属/租户/数据绑定、指标撤权，以及运行中/已完成回执的崩溃恢复。升级前仅有旧查询回执的等待任务也能继续。

前端 TypeScript/Vite 构建通过。在独立本地数据库与模拟模型 HTTP 下，实际界面完成“原问题 → 追问下方回答 → 同一任务完成 → 刷新恢复”；原问题、补充记录和指标结果均恢复，任务 ID 未改变。未提交的回答不写入服务器。

模型行为验证使用模拟响应，不代表真实模型的理解准确率；没有发送验收问题到真实模型。

## 使用方式与记忆边界

需要补充时直接填写追问下方的“回答这条追问”，点击“补充并继续查询”。顶部原问题只读，“修改原问题并新建查询”明确创建另一任务。当前任务最多补充 2 次，每次等待 24 小时。

普通推送查询将原问题、追问/回答、版本和操作回执保存在 PostgreSQL；模型收到有界的原问题和补充记录，并重新生成受限查询计划。工具分析另有结构化状态、证据引用与 LangGraph PostgreSQL 检查点。浏览器 localStorage 仅定位当前任务，数据仍从服务端读取。当前没有跨任务的个人偏好记忆、向量库检索或把整个聊天历史永久放入模型上下文的机制。
