# 语义层与可组合查询：需求及技术方案

日期：2026-10-10。

状态：用户已确认首批范围和技术方案。第一阶段已实现并部署至本地，自动化验证和页面验收见 [验证记录](validation.md#语义查询第一阶段)。代码与测试结果待用户人工验收；第二、三阶段尚未实现。

## 目标与分期

将六个指标的单指标查询升级为可组合查询，复用同一份指标定义、查询计划、权限检查和 SQL 编译器。扩展指标与维度时通过受信任的语义定义完成，避免按每种自然语言问题增加特殊 SQL 分支。

1. 第一阶段：语义目录、结构化查询计划、通用编译器、结果协议与界面；继续规则优先、LLM 兜底。
2. 第二阶段：补充经过验证的问题/查询计划示例，按问题检索相关语义定义与示例；独立建设评测集。
3. 第三阶段：引入受控 SQL Agent，探索第一阶段查询计划难以表达的问题。数据域、授权对象、修复预算和人工审核边界另出方案，不因第一阶段失败而自动启用。

## 第一阶段需求规格

### 支持范围

| 项目 | 首批范围 |
| --- | --- |
| 指标 | 现有六指标，每次 1–3 个不同指标；允许相同口径和筛选范围内组合 |
| 分组 | 巴西州、下单日期、下单月份；最多两个维度，日期与月份不能同时选择 |
| 时间 | 原有日/周/月与显式左闭右开区间；增加最近 1–12 个自然月的范围表达 |
| 筛选 | 州代码、订单状态、订单商品金额；最多 8 个条件，条件间为 AND |
| 运算符 | 州/状态支持 eq、ne、in、not_in；金额支持 eq、ne、gt、gte、lt、lte |
| 排序 | 分组字段或已选择指标，升序/降序；默认时间升序、州代码升序，指标排序增加稳定分组键 |
| Top N | 明确要求时返回 1–100 组；默认返回完整分组结果，超过 1000 组明确拒绝，不静默截断 |
| 结果展示 | 整体多指标卡片、统一明细表、州柱状图和时间趋势图；单位不同的指标分别绘图 |

州与状态使用枚举目录；不明名称要求澄清，不凭空选值。订单状态仅允许现有 Olist 状态（created、approved、invoiced、processing、shipped、delivered、unavailable、canceled）。中文名称通过受维护的别名映射或模型解析后验证。

“订单金额”明确指每单商品金额 item_amount，不含运费；不明确的“消费金额”“付款金额”要求澄清。比较值使用非负、最多两位小数的十进制数。NULL 不等于 0，也不会自动匹配不等于某值的条件；需要查询缺失值的能力另行扩展。

最近 N 个月包含分析基准所在月，从该月向前 N−1 个月的首日起，到基准次日止，界面标明末月可能未完整。例如基准 2018-08-15，“最近 3 个月”对应 [2018-06-01, 2018-08-16)。所有时间仍按历史数据当地墙上时间处理。

筛选先作用于订单集合，各指标再按自身口径计算。查询“已取消订单的有效订单量”不改变有效订单定义；有匹配订单且全部被口径排除时有效订单量为 0。没有匹配订单时保留无数据语义。GMV 金额缺失、交付时长样本、评价去重等沿用口径 v1。

### 必须明确的边界

- 允许多个明确、已授权指标，替代此前“一次多个指标即澄清”的规则；指标与手动选择冲突、表达有歧义仍需澄清。
- 不支持品类、卖家、支付方式和新跨表关联。现有 metric_orders 是订单粒度视图，品类分析需要先定义商品粒度和分摊规则，不能直接 JOIN 后复用订单指标。
- 本阶段不包含 OR/嵌套条件、聚合后筛选、同比/环比计算、归因、多轮上下文、报告生成和自由 SQL。这些请求返回具体能力边界，不降级为部分查询。
- 规则必须完整识别业务条件才命中；未知筛选、排序和否定表达不能被忽略。LLM 只补齐未识别条件，不能覆盖明确条件或扩大授权范围。
- 任一指标未授权时整个查询拒绝，不返回其余指标的部分结果。执行、落库、历史、SSE 和停止接口采用相同指标集合检查。

### 验收示例

| 问题 | 预期 |
| --- | --- |
| 本月 GMV 和有效订单量按州统计 | 两指标、州分组；规则完整命中则 0 Token |
| 最近 6 个月 GMV 和客单价按月统计 | 月趋势；两个指标分别绘图，客单价逐月重新计算 |
| 本月 GMV，只看圣保罗州 | 保留模型识别州名的兜底路径，筛选为 SP |
| 本月商品金额大于 100 的有效订单量 | 先按订单商品金额筛选，再计算有效订单量 |
| 本月 GMV 按州排名，取前 5 名 | 降序 Top 5，标明只显示前 5 组，不用这 5 组冒充全范围合计 |
| 本月 GMV 和平均评分（无评分权限） | 整体拒绝；撤销评分权限后该历史结果也不可查看 |
| 本月 GMV 按品类统计 | 提示尚未支持品类分析，不返回整体 GMV |
| 本月 GMV 比上月增长多少 | 提示本阶段尚未支持比较计算，不擅自删除上月条件 |

## 第一阶段技术方案

### 语义目录与查询计划

语义目录以随应用发布的 JSON 文件保存，由 Pydantic 严格验证；首批不新增 YAML 依赖、外部语义平台或配置管理服务。目录是受信任的版本化应用资源，用户和模型不能提交公式、物理字段、表名或 JOIN。

目录包含：指标 ID、名称、单位、口径版本、公式及样本表达式；维度 ID、物理表达式及排序；筛选字段的类型、枚举、运算符；逻辑数据集、订单粒度、时间字段和授权视图。表达式启动时做 AST/白名单校验，加载失败使服务不可用，不使用旧值或猜测默认值。

模型和规则均产生相同的 QueryPlan。以“最近 6 个月 GMV 和有效订单量按月统计，只看 SP”为例，解析器先解析时间，归一化计划为：

```json
{
  "version": 1,
  "metrics": ["gmv", "orders"],
  "dimensions": ["month"],
  "time_range": {"start": "2018-03-01", "end_exclusive": "2018-09-01"},
  "filters": [{"field": "state", "op": "in", "values": ["SP"]}],
  "order_by": [{"field": "month", "direction": "asc"}],
  "top_n": null
}
```

基准日期由服务端数据源配置给出。QueryPlan 不包含租户、角色、DSN、SQL 或任意表达式。数组长度、重复项、数值精度、日期范围、指标/维度组合均严格校验。未知字段拒绝。

旧 Intent 经适配器转成 QueryPlan；常见新表达由规则产生计划；规则未命中时模型使用同一 schema，返回计划或澄清。明确条件以约束对象独立保留并逐项核对，不能仅比较模型返回的总体描述。

### 编译与执行

编译器根据目录解析指标、维度和筛选 ID，组合 SELECT、WHERE、GROUP BY、ORDER BY。值始终绑定为参数，标识符和表达式只能来自受信任目录。多指标共用一个订单集合，一次 SQL 返回每组的指标及各自样本统计；均值和比例在分组内重新计算，不平均已聚合结果。

首批仍只查询 metric_orders，无新 JOIN。AST 白名单仅增加日/月分组和稳定排序需要的结构/函数，查询必须绑定时间范围。显式 Top N 是业务裁剪；普通查询用最多 1001 行探测是否超出 1000 组并明确拒绝，内部探测额度不能作为客户端可选额度。

维持只读账号、授权视图、10 秒 SQL 超时、20 秒单次模型超时及 Go 任务重试预算。根据新的计划长度调整模型输出 Token 上限，并测试截断响应不得执行 SQL；不添加解析器内部重试循环。

### 权限和结果协议

Go 的 allowed 检查必须读取整个指标集合，兼容旧结果的 metric 字段；新结果有任何未授权指标时整体不可见。无明确指标的待执行任务仍在 Python 解析后、Go 落库前验证；模型不能扩大 allowed_metrics。列表、详情和事件路径共用同一检查。

新结果带 result_version=2、归一化查询计划、指标元信息列表、分组字段列表、结果行、指标级样本统计、SQL/参数和 parser/Token 用量。金额及高精度数值保持十进制字符串，NULL 保留。Top N 结果标记裁剪范围，不对比例或均值的分组值求和、求平均来生成总计。

单指标旧输入保持兼容；旧任务结果保留原 JSON，无数据库结果批量改写。前端根据结果版本渲染：旧结果沿用原展示，新结果支持多个卡片/序列和表格，显示筛选、口径和数据依据。原单指标下拉作为明确约束，多指标可先由问题表达，避免本阶段扩展复杂查询编辑器。

### 改动模块与部署

| 模块 | 计划改动 |
| --- | --- |
| Python runtime | 语义目录、QueryPlan、规则/模型解析适配、SQL 编译、结果规范化、安全校验 |
| Go API / store.Input | 扩展必要的计划约束与多指标授权识别，兼容已有任务及权限撤销检查 |
| React | 新结果类型、多个指标展示、时间图表、筛选及 Top N 标识，兼容历史结果 |
| Docker / 云模板 | 将语义 JSON 打包进 agent 镜像；规则与模型共享同一目录版本，本地和云采用相同发布资源 |

第一阶段复用现有 Go/Python/React、PostgreSQL/MySQL，不新增服务、不重导 Olist。确认现有镜像 COPY 范围可包含目录；规则和模型必须在同一部署版本读取同一目录。云端继续通过环境/Secret 注入凭据，目录不包含凭据。

## 验证与交付

- 独立构造订单数据核对多指标、不同样本分母、日/月与州联合分组、金额与状态筛选、排序和 Top N；预期值不得复制编译器公式。
- 原始 Olist CSV 独立计算月/州分组和筛选结果，与真实 MySQL 执行比较；保留原六指标黄金回归。
- 测试不同单位、Decimal、NULL、真实 0、无样本、空月份不自动补 0、末月不完整和组数超限。图表不得把 NULL 转成 0。
- 模型 mock 验证完整规则零调用、计划 schema、条件不遗漏、禁止 SQL/越权字段、超时/截断/无效响应不执行；少量真实调用检查集成链路，单独记录消耗和边界。
- Go 单元和真实 PostgreSQL 集成测试覆盖多指标撤权后历史/列表/SSE 不泄露、旧任务兼容、停止与重试预算；Python 单元和真实 MySQL、安全攻击集回归。
- TypeScript/生产构建与浏览器验收多指标卡片、月趋势、联合分组、明细和旧历史；验证 Compose 镜像与本地启动，校验云模板资源打包。未在云账号部署不得标记云验收完成。
- 每批代码改动验证后提交 commit；交付代码、测试结果和可操作示例供用户人工验收。未完成的验收项目明确列出。
