# 用户意图理解评测与求职展示证据

日期：2026-10-12。

状态：2026-10-12 用户确认先补独立评测和展示证据，再做受控多轮问数，并确认以下需求及技术方案进入实现。题集、scorer、配对执行和报告已实现；代码、测试及实测结果供人工验收，题单预期仍待人工复核。

## 目标与现有基础

回答三个问题：规则能够完整理解多少问题，模型补足了多少表达变化，成功返回的答案是否保留用户全部条件。展示同时提供成功案例、失败类型、数据来源和复现方法。

现有 `evals/cases.py` 有 120 条表达、35 个业务或权限组。50 条规则表达来自 10 个问题各加五种前缀，25 条陌生表达来自五个州名问题各加五种前缀。现有独立 CSV oracle 已检查计划、结果、排序、样本及 NULL；新增工作复用这些能力，并增加更丰富的表达和可解释的分项判定。

ECS 真实 Olist 核对已验证八个规则案例及一个模型案例，证明链路和这些答案正确，不能作为陌生表达总体正确率。旧本地报告对应历史工作树，不能直接作为本次提交的实测结果。

## 需求规格

### 题集与人工标注

新题集独立版本化，首批 90 条表达，至少 45 个业务或边界意图组。30 条常用支持表达、30 条陌生支持表达、30 条边界表达；边界包含缺条件 8 条、冲突 6 条、范围外 8 条、权限 8 条。同组改写不能跨开发与验收分区，按组分层划分，报告实际分区数量。

陌生表达覆盖词汇替换、语序变化、口语、省略但可唯一确定的表述、复合筛选、否定和排序；不能只增加礼貌前缀。仅测试现有六指标、州或日或月分组、支持的筛选、排序与 Top N。需要前文才能确定的省略属于边界题，多轮能力尚未加入。

每条题由需求人工标注预期状态、指标、日期范围、维度、完整筛选、排序、Top N、需要澄清或拒绝的原因。权限来自测试身份和服务端配置。预期不能从实际解析器或模型输出反推；人工复核状态单独记录，未经复核的题单不能称为人工标注验收集。

题目的预设类别和实际解析路径分别记录。陌生表达若被规则完整识别，照常计入规则覆盖，不能强迫模型调用以提高模型题数量。对于当前不支持的表达，保留失败与边界说明，不在这批顺便扩充解析规则。

开发与验收题集按业务意图组隔离。验收题用于针对性调优后移入回归，并补充新验收题。现有 CI 冻结题集、oracle 与门槛保持其版本，新题集单独评审和建立基线。

### 同题对照

在同一个源码提交、夹具、权限、语义目录和分析基准下运行两种模式：仅规则，以及规则加真实模型兜底。仅规则模式在独立评测进程中关闭模型配置；完整模式保留现有规则优先行为。两种模式都运行全部选定题，不能像现有 deterministic 模式一样跳过陌生表达。

以全部支持题为固定分母，分别报告正确完成数。模型补足数是仅规则未正确完成、完整模式通过且确实调用模型的配对题数量；另报仅规则通过而完整模式失败的题数，以及两种模式正确完成率之差。模型增益只描述这份题集，不能推断真实用户分布。

### 判定与指标

| 判定 | 检查内容 |
| --- | --- |
| 意图一致 | 指标集合、日期、维度、全部筛选、排序与 Top N；允许事先定义的语义等价归一化 |
| 条件完整 | 缺失、擅自增加、否定反转、运算符或取值错误分别记录；多余条件同样失败 |
| 数值正确 | 独立 CSV 计算的组键、数值、NULL、样本数、排除数量及业务顺序 |
| 边界处理 | 缺条件、冲突、范围外须得到对应澄清或拒绝，且不执行 SQL |
| 权限正确 | 未授权指标整体拒绝，跨租户访问不可见，模型与结果不能扩大权限 |

全部支持题作为主指标分母。失败、超时、无效 JSON、供应商故障与拒答均不能从分母删除；另外显示执行失败原因。成功返回率与业务正确率分开。

报告包含规则完整正确覆盖率、配对模型补足数、模型路径意图正确率、结果正确率、计划与结果均正确的完成率、条件错误数、边界判定率、权限判定率。每个比例附分子和分母；未返回计划的题计主指标失败，计划细项标为不可观察，不虚构条件遗漏数量。

计数和金额精确比较；均值与比例沿用绝对误差 0.0001；NULL 与真实零单独比较。按照独立夹具与真实 Olist 分别出报告，不能合并为一个准确率。

### 稳定性与调用预算

真实模型验收在冻结题集上跑三轮，每轮分别列出结果，并统计逐题三轮全部通过和出现波动的数量。缺少真实模型配置时记录未执行，mock 与离线验证不能替代。

默认串行，真实模式必须显式启用。每轮出站前硬限制最多 120 次模型请求，含任务重试；三轮总上限 360 次。预算耗尽时终止并标记报告未完成，不输出通过结论。这个上限是安全预算，不是预计消耗。

记录实际请求数、已知输入与输出 Token、未知用量次数、任务及模型阶段耗时和重试次数。未配置价格表时只报告用量，不虚构费用。模型名称与 endpoint 配置标识可关联版本，但供应商权重版本若不可知则明确标记。

## 技术方案

### 文件与复用范围

- `evals/understanding/`：新增题集、标注 schema、版本及复核状态，独立于现有冻结案例。
- `scripts/evaluate_understanding.py`：新增仅规则与完整模式的配对执行入口，支持分区、案例诊断、真实模式、三轮及调用预算。
- `evals/understanding/scorer.py`：独立分项比较预期计划与实际计划；复用现有独立 CSV 数值算法，禁止导入运行时公式、解析器或编译器生成预期。
- `scripts/report_understanding.py`：从报告生成求职展示摘要和逐题差异，摘要中的统计必须可追溯到报告。
- `docs/user-understanding-evidence.md` 与 README：在实测后添加题集构成、规则覆盖、模型增益、条件错误、典型案例、失败与复现命令。

复用现有 Go fixture、任务 worker、SQL 观测、遥测和只读测试数据库配置。必要的通用提取必须保持旧评测输出兼容，并通过现有门禁回归；新报告不冒充正式发布镜像门禁。

不增加 Agent 框架。这批是固定评测流程，直接使用现有模型传输与 QueryPlan 即可。是否增加框架应由后续实际编排需求决定。

### 报告与展示

报告保存代码完整 SHA、题集及复核版本、夹具与 scorer 摘要、runtime 及目录摘要、模型配置标识、时间、模式、轮次、完成状态、每题判定和实际解析路径。配对比较先校验这些身份一致；缺题、重复 ID、数据版本不一致和未知报告版本应拒绝汇总。

公开展示使用人工构造问题、预期计划、通过或失败的字段差异、独立结果摘要和用量。公开题目用于开发或演示分区；保持独立的未展示验收题用于后续测试。详细运行结果默认写入忽略目录，密钥、Cookie、DSN、原始供应商响应和私有数据不进入提交。

至少展示三类案例：规则完整命中；仅规则不能正确完成而模型保留全部条件并答对；澄清、权限或范围外被正确拦截。若模型有失败，展示其具体原因，不能只筛选成功案例。

### 数据与环境

主评测使用显式指定的测试 PostgreSQL、MySQL 与隔离身份，禁止以生产数据库承担创建和清理夹具。真实 Olist 验证复用只读数据核对路径，在报告中独立标明环境和数据摘要；上线主机的只读复核另行执行，不修改生产账号或部署。

### 验证与交付

验证 scorer 能识别遗漏条件、额外条件、否定反转、错误排序、错误 Top N、正确数字但错误计划、NULL 转零及错误边界原因。验证配对统计不会把失败删除、把未知用量置零或把规则成功计为模型增益。

在真实隔离双库运行完整链路，记录计划、SQL 调用和结果；检查模型预算包含重试，报告身份与复现命令完整。原有 Python、Go 及现有确定性质量门禁作为回归要求。真实模型三轮和独立 Olist 核对在环境具备后执行，未完成项直接列出。

按批提交已验证改动：先题集与 scorer，再执行和报告，再真实运行证据与 README。代码和测试结果交付后由用户人工验收；不自动 push、合并或部署。

## 后续受控多轮问数

本次只预留后续设计方向：维护服务端 QueryPlan，受限修改由规则或模型提出，逐轮重新校验指标、时间、权限和组合条件，澄清或失败不能覆盖最后一次有效计划。并发消息采用版本检查，任务重试不能重复推进会话状态。

示例“只看两个州，取前三名”没有指定哪两个州，需要澄清；州分组只选两个州时最多返回两组，不能生成第三组。Top N 若没有明确排名指标或方向，也应根据已确认规格决定是否澄清。该能力另行确认需求、技术方案和测试，不在本批实现。
