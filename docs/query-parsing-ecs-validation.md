## 首次失败与修正

首先测试已验收提交 `865d0903d2a2797022bea7e2b1723eb9b22932ef`，线上仍保留旧版。候选三轮仅为 24/28、21/28、19/28，出现输出截断、格式错误、限流和 HTTP 错误；完整失败记录保留在证据中。

诊断发现目标网关在 512/1024 输出上限下，某些响应的预算全部用于推理，最终正文为空。目标网关不接受供应商的关闭思考参数或 reasoning_effort 参数。供应商文档说明思考模式及推理 Token 行为，见 [DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/)；目标网关兼容性以本次实际 HTTP 诊断为准。

修正提交 `ac4b4f7` 保留现有三字段请求协议，允许私有部署配置输出预算，并补充首轮/追问共享的州范围语义说明。单次解析一次模型调用、20 秒超时和严格截断拒绝继续生效。最终候选按至少 20 秒间隔启动模型请求，本轮没有模型服务错误。提高预算与调整提示分别解决输出和语义问题，不能据此认定所有句式都能完成。

全部测试包含首次失败、诊断和 HTTP 验证，共 66 次模型请求尝试，已知 Token 92,760；15 次尝试用量未知，未当作零消耗。另有 1 次模型列表元数据请求。切换后的 HTTP 测试为 4 次模型调用、7,123 Token、未知用量 0。失败响应的已知用量从遥测补记，不仅统计成功结果 usage。
