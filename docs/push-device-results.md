# 推送与设备分析实施验证

日期：2026-10-18，上海时区。分支：`codex/push-device-analytics-20261018`。需求及业务口径已经用户确认，见 [规格](push-device-spec.md)。

## 交付行为

平台提供推送与设备分析工作台、结构化查询、自然语言计划解析、单期/Top N 汇总与两期推送下降核查。默认数据域为推送初始化，可信映射按 `domain=push` 选择运行协议；订单域为显式历史兼容配置。

设备以 `(app_id,device_id)` 为粒度，状态历史在导入时先归并为互斥区间。权限开启且至少一个有效 Token 判有效，明确关闭权限或全部 Token 失效判无效，其余未知。活跃由应用前台事件统计，不能将推送点击替代为应用活跃。

查询使用自定义带时区区间、独立回执观察时长及设备状态时点。SQL 从授权计划编译，绑定筛选参数；查询账号只能读取授权视图，原始表不授权。导入拒绝覆盖 schema，并在发布时记录数据摘要。重复回执先聚合，重试不增加逻辑投递量，比率按总分子和总分母重算，零分母为空。

推送协议接入原有 LangGraph、账本、持久事件、围栏和任务读取授权。规格不能跨数据域混用；分子、分母和派生指标依赖必须全部授权。数据截止、起点、模拟标识和目录进入源绑定，单步任务也在绑定变化后拒绝读取。

## 实际执行的验证

1. 完整回归 **373 项通过，零跳过，115.55 秒**。配置专用回环 PostgreSQL、现有 Olist CSV 及本地 `pg_dump`/`pg_restore`；该计数包含历史订单、平台、图检查点、恢复与新增推送测试，不是推送模型准确率。
2. 推送与受影响分析测试执行 **50 项通过**；新增覆盖结构化 API/Worker/SSE、固定流程、模拟 HTTP 自适应决策、短引用及输入预算、完成证据、指标依赖、权限、数据绑定、只读权限、应用裁剪、不可变发布、冲突回执和状态重叠。收尾后再次执行推送专项 **24 项通过，32.42 秒**。
3. 前端 `npm run build` 通过 TypeScript 与 Vite 构建。既有图表包仍有体积提示，不影响构建成功。
4. 独立本地预览使用新建测试库、实际只读查询、API 与 Worker。页面已核验推送按通道查询、设备按厂商查询及固定流程报告与步骤。预览为固定流程、已确认规格，**没有调用真实模型**。
5. 示例页面的 2026 年 7 月设备查询结果：设备 600、有效 370、无效 208、活跃 579，未知状态 22；这是该期末状态，不能与 10 月快照有效数混用。

Windows 沙箱回环网络阻止了初次连接；专用 PostgreSQL 与测试在相同执行环境后完成上述结果。没有修改或连接业务云端数据库。

## 验证限制

- 自适应模型协议使用模拟 HTTP 响应验证，真实模型语义理解、任务成功率、成本与延迟尚未重新评测。原 Olist 的 A/B/C 分数不能移用。
- 推送查询不使用订单多轮计划。分析任务的条件补充复用两轮 interrupt；设备分析不支持按多值通道分组，避免重复计数。
- 仅验证本地实现、数据与页面。本次未推送、合并、切换云端服务，也不将历史云端发布报告写成当前推送能力的部署证据。
- 用户原有 `.github/rulesets/master-pr-only.json` 修改未纳入此次提交。
