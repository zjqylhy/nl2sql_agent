# 技术方案 v1.0

已确认。Go 负责 HTTP、鉴权、权限与元数据；Python 负责模型意图、时间解析、SQL AST 安全检查与分析数据库只读取数。浏览器不直接调用 Python。Go 从当前账号构造可信权限上下文，Python 从服务端租户/角色配置选择受限 MySQL 账号，模型不能选 DSN 或租户。

Go 使用 PostgreSQL 持久化账号、会话、任务、事件及 outbox，任务变更采用条件更新。Cookie 随机会话令牌仅存哈希；CSRF 要求写操作 Origin 同源；线上强制 secure cookie。登录失败统一提示，限速；权限变化后会话请求重新加载账号。管理员 CLI 用独立管理连接 bootstrap；应用启动执行数据库迁移属于部署管理职责。

M1 任务按一用户一活跃任务调度，outbox 行领取使用数据库租约。Python API 超时短于租约；Go 在停止时取消调用，在结果落库前再次校验状态和执行版本。崩溃时过期任务有限恢复，超出预算终止。历史事件带序号，轮询 PostgreSQL 后通过 SSE 发出，Last-Event-ID 支持续传；关闭浏览器不会停止任务。

所有指标经过订单粒度聚合视图。只读查询仅针对 metric_orders，数据库账号不得读取基表；地区限制在 SQL SECURITY DEFINER 视图内表达。SQL AST 校验仅允许 SELECT、单授权表、批准列和函数，不允许 CTE、子查询、UNION、写操作、系统表、用户变量、任意函数。SQL 参数独立绑定，LIMIT 上限 1000、执行超时 10s。

M1 支持显式指标/时间输入，先尝试完整的受限规则解析（单指标、地区、日/周/月及显式区间），命中时不调用模型。支持范围内的陌生表达才使用已配置的真实 LLM 兜底；未配置模型时要求澄清。模型输出不含自由 SQL，受 schema 与语义校验约束，不能覆盖已明确的条件。数据不可用时明确失败，不退回模拟数据。

部署用 Compose 包含 PostgreSQL、MySQL、agent、Go API、前端。Redis/Celery、对象存储、LangGraph checkpoint 随 M2/M3 接入。数据库和 agent 不映射公网端口，反向代理提供同源路由和 TLS。生产密码与 API 密钥通过环境/secret 注入，仓库只保存样例。备份分别覆盖平台 PostgreSQL、MySQL 和报告对象。

## 已确认并实现：规则优先、LLM 兜底

对应 [已确认需求变更](spec.md#已确认变更规则优先llm-兜底)。用户已确认技术方案；app.py 按规则结果选择解析器，代码和测试待人工验收。

规则解析器以 Intent 表示命中，以 RuleMiss、Clarification、Unsupported 区分未命中、需澄清和不支持，仅捕获 RuleMiss 触发模型。question_constraints 共用范围和冲突检查；rule_remainder 检查受限词法表达是否完整消费，分组、筛选、未知条件与否定表达不能静默变成整体统计。已明确的日期、州范围和手动输入通过 IntentConstraints 在模型返回后再次核对。

路由顺序：内部鉴权与数据源授权 -> 范围/冲突检查 -> 尝试规则 -> 命中则校验意图 -> 未命中且有模型则调用 LLM -> 校验模型意图及手动约束 -> 指标授权/时间范围检查 -> 现有 SQL 编译、安全校验和只读执行。两条路径均不能从用户或模型选择数据源。

模型收到已明确的意图字段，仅解析剩余表达；内部判定标志不放进模型 JSON 上下文，成功响应只允许六个意图字段。严格校验返回字段及约束一致性。保持单次模型调用 20 秒超时、max_tokens=800，沿用 Go 已有任务重试预算。usage.parser 和 tokens 记录实际解析方式与提供商返回的用量，模型要求澄清同样保留用量，不记录密钥或密码。复用现有前端展示，无新增依赖或部署组件。

验证覆盖：模型已配置时常见问题完全不调用模型且 Token 为 0；规则未命中调用模型并正确编译筛选；没有模型时澄清；缺失条件、冲突、越权和超范围均不调用模型/数据库；手动约束不被覆盖；未知维度与筛选不被忽略；模型错误/超时/无效输出不执行 SQL。本地容器验证规则与真实模型兜底两条路径，金额均与原始 CSV 独立计算一致；详情见 [验证记录](validation.md)。
