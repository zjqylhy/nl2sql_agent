# 技术方案 v1.0

已确认。Go 负责 HTTP、鉴权、权限与元数据；Python 负责模型意图、时间解析、SQL AST 安全检查与分析数据库只读取数。浏览器不直接调用 Python。Go 从当前账号构造可信权限上下文，Python 从服务端租户/角色配置选择受限 MySQL 账号，模型不能选 DSN 或租户。

Go 使用 PostgreSQL 持久化账号、会话、任务、事件及 outbox，任务变更采用条件更新。Cookie 随机会话令牌仅存哈希；CSRF 要求写操作 Origin 同源；线上强制 secure cookie。登录失败统一提示，限速；权限变化后会话请求重新加载账号。管理员 CLI 用独立管理连接 bootstrap；应用启动执行数据库迁移属于部署管理职责。

M1 任务按一用户一活跃任务调度，outbox 行领取使用数据库租约。Python API 超时短于租约；Go 在停止时取消调用，在结果落库前再次校验状态和执行版本。崩溃时过期任务有限恢复，超出预算终止。历史事件带序号，轮询 PostgreSQL 后通过 SSE 发出，Last-Event-ID 支持续传；关闭浏览器不会停止任务。

所有指标经过订单粒度聚合视图。只读查询仅针对 metric_orders，数据库账号不得读取基表；地区限制在 SQL SECURITY DEFINER 视图内表达。SQL AST 校验仅允许 SELECT、单授权表、批准列和函数，不允许 CTE、子查询、UNION、写操作、系统表、用户变量、任意函数。SQL 参数独立绑定，正常结果上限 1000 组、执行超时 10s；内部 LIMIT 1001 仅用于超限探测，超过 1000 组明确拒绝，不返回截断结果。

M1 支持显式指标/时间输入，先尝试完整的受限规则解析（单指标、地区、日/周/月及显式区间），命中时不调用模型。支持范围内的陌生表达才使用已配置的真实 LLM 兜底；未配置模型时要求澄清。模型输出不含自由 SQL，受 schema 与语义校验约束，不能覆盖已明确的条件。数据不可用时明确失败，不退回模拟数据。

部署用 Compose 包含 PostgreSQL、MySQL、agent、Go API、前端。Redis/Celery、对象存储、LangGraph checkpoint 随 M2/M3 接入。数据库和 agent 不映射公网端口，反向代理提供同源路由和 TLS。生产密码与 API 密钥通过环境/secret 注入，仓库只保存样例。备份分别覆盖平台 PostgreSQL、MySQL 和报告对象。

## 已实现：受控多轮 QueryPlan

Go 将会话成功计划与澄清草稿分别持久化，每轮以 request_id 幂等接纳和会话版本控制并发。Worker 读取固定快照，执行版本隔离重试；成功、澄清、失败或停止在事务内释放当前任务。会话只对创建者可见，旧任务接口也检查该所有权。详情与每次执行重新检查权限和数据绑定。

处理过程为：当前文字与可信快照 → 规则完整解析，未完整命中则一次 LLM 受限 Delta → 应用明确修改与依赖清理 → 校验指标、时间、筛选及组合 → 语义目录编译绑定参数 SQL → AST 白名单和只读视图查询 → 条件更新持久计划 → 界面显示继承及修改。缺条件仅保存受限草稿，不生成或执行 SQL；模型不接收整段聊天、结果行或 SQL。

这批会话记忆不依赖 Agent 框架，规格见 [多轮设计](controlled-multiturn-spec.md)，量化证据见 [多轮实测](multiturn-evidence.md)。

## 已确认并实现：规则优先、LLM 兜底

对应 [已确认需求变更](spec.md#已确认变更规则优先llm-兜底)。用户已确认技术方案；app.py 按规则结果选择解析器，代码和测试待人工验收。

新问题统一解析为 QueryPlan，旧 Intent 仅保留适配用途。共享受限语法从原文当前位置匹配完整子句，并记录子句类型及原文区间。未知否定或修饰结构不从内部搜索肯定关键词；“不包含 SP”产生排除筛选，小写州代码按州词元归一化。未指定维度的“分组”“趋势”不能当作连接词删除。

完整句式且条件齐全时规则直接返回；未覆盖表达交给已配置的 LLM 解释完整原文。手动输入和完整语法确定的条件参与一致性检查，未覆盖子句的局部猜测不锁定模型。缺条件或冲突时返回澄清，已确认超出能力时提示边界；不能因出现“不看”“不要”就直接拒绝。未配置模型时未覆盖表达仍要求改写。

首轮模型返回完整 QueryPlan，多轮模型返回受限 Delta；单次 Python 解析至多一次模型调用，不增加内部重试。模型获得授权指标及业务定义、受限 Schema、分析基准和可信快照，禁止 SQL、物理表达式或数据源。Schema、目录、筛选矛盾、日期、全部指标权限和 SQL 安全检查继续生效。模型截断、空操作、无效结构或超时不执行 SQL、不推进有效计划。

语法日志只记录类别、覆盖原因和区间，不记录问题或筛选值。独立题集检查完整计划与原始 CSV 结果，结构合法不等于语义理解正确。需求、范围和验收用例见 [解析可靠性方案](query-parsing-reliability-spec.md)。

## 演进方案：语义目录与 QueryPlan

用户已确认第一阶段方案，见 [语义查询规格](semantic-query-design.md)，已实现并部署至本地。`catalog.json` 随镜像发布并在启动时严格验证公式及字段。规则与模型直接生成 `QueryPlan`，旧 Intent 保留适配器并复用 `compile_plan`：指标和维度表达式来自目录，筛选值参数绑定，统一聚合、排序和内部超限探测。

每次最多三个指标、两个维度；日期与月份不能同时分组。AND 筛选仅允许州、订单状态和不含运费的商品金额。金额比较使用 Decimal；指标分母与样本按分组重新计算。结果协议 v2 含指标元信息、计划、指标级数值与样本、SQL/参数及用量。前端展示多个卡片、独立图表和明细表，NULL 不转 0；旧 JSON 仍按原协议展示。

Go 在结果落库及历史、列表、SSE、停止路径检查指标元信息和计划的完整集合，任一指标撤权则整体不可见。模型不能改变明确时间、维度、筛选、排序和 Top N；枚举单值 eq/in、ne/not_in 按等价语义比较。新问题统一使用计划输出预算（运行时默认 512 Token，部署可通过 `LLM_PLAN_MAX_TOKENS` 覆盖）；超时仍为 20 秒。截断、无效计划、越权和条件不一致均不执行 SQL。没有新增服务或数据库迁移；受控 SQL Agent 尚未实现。
