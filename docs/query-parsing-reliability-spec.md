# 自然语言查询解析可靠性需求与技术方案

日期：2026-10-15。

状态：用户已确认需求与技术方案，并于 2026-10-15 确认本次代码及已报告的自动化验证结果，人工验收通过。真实模型三轮及 MySQL 集成验证需要补齐环境，仍未完成。

实现及当前验证范围见 [解析验证记录](query-parsing-validation.md)。

## 问题与目标

改动前，解析器通过删除已匹配片段、检查剩余文字判断规则是否完整识别。这个判定不能证明语义正确：`rule_remainder` 会删除“不包含”，使“本月 GMV，不包含 SP”与“本月 GMV，只看 SP”得到相同的州条件。另一方面，“不看”被直接判为 Unsupported，规则没有理解的受支持表达无法进入模型兜底。州代码正则仅接受大写，旧 Intent 也只能直接表达州包含条件。

本次将规则收缩为明确句式的快捷路径，让未覆盖的表达有机会交给模型，减少错误执行和多余澄清。首轮和多轮统一使用这个原则；业务能力继续由已有语义目录、QueryPlan 和 PlanDelta 限定。

规则命中、模型输出合法 JSON、Schema 校验通过，都不能单独证明自然语言语义正确。验收须比较独立标注的完整业务计划，并记录模型仍然可能出现的遗漏和误解。

## 需求范围

1. 规则直接返回计划必须满足完整句式和操作范围检查，禁止通过删除任意否定词或业务文字得到成功。
2. 覆盖包含、排除、取消筛选三种不同操作，支持州代码大小写归一化。只有识别为州代码的词元才转大写，保留原始问题。
3. 未覆盖句式交给已配置的模型解释完整原问题；规则未命中不等于业务能力不支持。
4. 仅在信息确实缺失、存在冲突或歧义、请求超出能力，以及未配置模型而规则无法识别时要求用户补充。模型调用失败继续报告服务错误，不伪装为用户条件不明确。
5. 完整规则路径保持零模型调用；单次 Python 解析至多调用一次模型，不增加内部重试。现有任务级重试、Token、超时和用量记录继续生效。
6. 不扩大指标、维度、筛选、关联、比较和权限范围；不改变 QueryPlan、PlanDelta、结果及会话持久化的外部协议。

## 解析决策

| 识别结果 | 处理 |
| --- | --- |
| 完整匹配已支持句式，条件齐全且无冲突 | 构造并校验计划或修改操作，规则直接返回 |
| 有未覆盖文字，或者否定、修饰、操作范围不能由语法确定 | 模型解释完整原问题，规则结果只提供提示 |
| 完整匹配的句式缺少必填参数或有明确矛盾 | 返回具体澄清；多轮保留已验证的草稿 |
| 已确认请求超出当前能力 | 返回具体能力边界，不执行部分查询 |
| 规则未覆盖且未配置模型 | 说明当前表达未被识别，请用户改写或补充 |
| 模型超时、输出截断或结构无效 | 返回服务错误，不执行 SQL，不推进有效计划 |

不再因原文中孤立出现“不看”“不要”“不是”等词直接判定 Unsupported。范围外判定依据完整请求的操作及对象；无法通过规则确定时由模型解释，不能只因未知句式就提前拒绝。

## 技术方案

### 完整句式与识别来源

新增共享的受限语法解析模块，明确列出指标、日期、分组、筛选、排序、Top N 及连接方式的产生式。正则可用于识别词元或完整子句；成功路径必须由完整语法覆盖所有业务内容，而不是多次替换后检查空字符串。

解析结果区分完整匹配、未覆盖、缺条件及冲突，记录字段对应的原文区间和操作类型。只忽略定义好的空白、标点和礼貌前后缀。对未被文法接受的修饰词、连接关系和否定结构整体转模型，不截取其中的肯定子串作为已确认条件。

首批规则保持现有常用肯定查询和受控追问，并增加完整的州排除句式，例如“不包含 SP”“不看 sp，看其他州”。“不要只看 SP”不得用“只看 SP”的包含规则命中；上下文确定操作时按下述验收标准处理，否则进入模型或澄清。

语法完整覆盖是一项可检查的工程条件，其正确性仍依赖文法设计及测试，不宣称能够证明任意自然语言含义。

### 首轮统一 QueryPlan

`app.parse_query_plan` 成为首轮统一入口，避免根据个别关键词把排除表达送进只能表示包含筛选的旧 Intent。现有输入字段保持兼容；旧 Intent 适配器及历史结果可以保留，但不再作为新自然语言问题的默认分流路径。

完整规则生成 QueryPlan；未覆盖表达调用现有 ModelTransport，发送原始问题、分析基准日、授权指标、语义目录中的允许项及 QueryPlan Schema。模型返回完整计划或澄清，不允许 SQL、表名、公式和数据源。

手动输入、可信上下文和语义目录仍是硬约束。自动词元匹配只作为非强制提示；只有完整子句解析且作用范围确定的条件才能参与明确条件一致性检查。未覆盖子句中的猜测不得锁定模型输出。

### 多轮完整问题兜底

保留最后成功计划、独立澄清草稿及受限操作应用机制。完整匹配时生成 PlanDelta；未覆盖时模型接收原始追问、基准计划、相关草稿及完整操作 Schema。不得仅因规则未提取到修改目标而跳过模型调用。

原有 allowed 目标集合不再由关键词命中作为模型调用的前提或唯一边界。授权、操作字段类型、筛选 ID、操作数量及计划组合仍由代码验证；仅完整子句确定的操作可作为必须保留的修改，部分匹配的操作只作提示。模型未涉及字段保持不变的能力通过操作范围检查及独立评测验证，不宣称 Schema 本身能验证用户是否提出该修改。

初始问题与追问共享单次模型调用预算，防止首轮失败后再经多轮入口调用第二次模型。未完整理解的原始草稿条件继续保留，不能被无关追问消除。失败、澄清及越权均不能覆盖最后成功计划。

### 校验和诊断

候选计划继续经过 Schema、目录 ID、枚举、运算符、分析基准、完整指标权限和 SQL 安全检查。业务能力不支持时不执行删减条件后的部分计划。

诊断记录解析路径、未覆盖原因、完整句式标识及条件来源，用于解释为何调用模型或要求澄清。模型 Token 和调用次数沿用现有遥测；公开报告不写入密钥或私有数据。

代码校验能确定结构、允许范围及已明确条件是否符合约束；模型是否遗漏未知表达中的含义，需要通过独立标注评测暴露，不能把结构合法当作语义正确。

## 验收用例

除专门说明外，首轮完整问题使用“本月 GMV”作为指标和时间前缀。多轮基准为最近六个月 GMV、按月分组且仅限 SP；修改州条件后，指标、时间和分组保持不变。

| 场景 | 独立预期 |
| --- | --- |
| 只看 SP | state in SP |
| 只看 sp | 与大写 SP 相同 |
| 不包含 SP | state not_in SP，不得得到包含条件 |
| 排除 SP | 与“不包含 SP”相同 |
| 不看 sp，看其他州 | state not_in SP，不隐式增加州分组 |
| 只看 SP 和 RJ | state in SP,RJ |
| 不包含 SP 和 RJ | state not_in SP,RJ |
| 不要只看 SP，查看全部州 | 没有州筛选；权限仍由数据源和授权范围限定 |
| 不要只看 SP | 首轮范围未确定则澄清；不得自动解释为排除 SP |
| 只看 SP，但不要排除 RJ | 识别包含与否定的关系，条件冲突则澄清；不得静默取其中一半 |
| 明确要求同比或按品类统计 | 提示当前能力边界，不返回删去比较或品类后的计划 |
| GMV，只看 SP | 缺时间且没有可信上下文，询问时间，不编造日期 |
| 多轮：取消州筛选 | 清除州筛选，保留其他条件 |
| 多轮：不要只看 SP，查看全部州 | 清除州筛选，不添加排除条件 |
| 多轮：不看 sp，看其他州 | 原 SP 包含条件改为 SP 排除条件，不产生互相矛盾的 AND 条件 |
| 多轮：未覆盖但可表达的清晰追问 | 有模型时允许模型解释，不能因规则 allowed 为空直接要求改写 |
| 多轮：未知表达后补充无关分组 | 未解决的原条件仍在草稿中，有效计划不变 |
| 模型新增未授权指标或无效筛选 | 拒绝，不执行 SQL，不推进会话 |
| 模型输出无效 JSON、截断或超时 | 服务错误；单次解析不再次调用模型 |

相近表达使用独立预期构成成对测试，检查否定反转、条件遗漏、擅加分组及额外筛选。未覆盖句式的 mock 测试检查是否真实调用模型、是否携带完整原文、是否错误锁定局部条件；不能只检查最终 JSON 可解析。

## 验证与交付

先补失败用例，再实现共享语法、首轮统一入口及多轮兜底调整。回归现有规则、计划、权限、多轮及评测脚本测试；确认规则直接成功的完整计划与独立标注一致，澄清和失败路径 SQL 调用为零。

扩展现有独立理解与多轮题集，分别报告错误规则直出、有效请求被多余澄清、模型补足和模型失败的数量；原有失败不从分母删除。规则覆盖率可以下降，不能以提高覆盖率为理由接受错误直出。

具备真实模型和隔离验证环境时，按现有显式真实模式和调用预算运行三轮固定题单，独立核对完整计划及 CSV 结果。缺少环境时明确列出未完成项，mock 不替代真实模型语义验收，不自动部署到现有 ECS。

每批项目改动单独 commit，保留用户已有工作区修改。实现和验证结果提交人工验收；推送、合并和部署另行授权。
